## 接地校验（AnswerGuard）

> 出处：原 `docs/10-接地校验.md`（已合并，正文未改写）

> 这份文档回答三个问题：**为什么光校验引用编号不够**、**我们怎么校验**、**它挡不住什么**。

### 1. 问题：编号合法 ≠ 出处真实

在接这个功能之前，`QaService` 只做一层校验：

```java
// 旧逻辑（QaService 第 4 步）
if (n >= 1 && n <= hits.size()) { ...合法... } else { ...编造... }
```

它只能发现"资料只有 3 条，模型却标了 `[5]`"这种**编号越界**。

线上真实翻车（2026-11-22 记录）：

| 项 | 内容 |
|---|---|
| 问题 | 违纪处分有哪几种？ |
| 模型回答 | 「共有五种：[2] 具体为：警告、严重警告、记过、留校察看、开除学籍。[2]」 |
| 编号校验 | **通过**（资料 3 条，`[2]` 合法） |
| 事实真相 | 这份清单在**第 3 块**（chunkId=834），不在第 2 块。第 2 块结尾恰好被切分劈断在「给予下列之一的处」 |
| 危害 | 用户点开 [2] 看不到处分清单 → 认为系统在编 → 信任崩塌 |

**结论：内容对、出处假，比内容错更难发现，也更伤信任。** 这就是要加第二层校验的原因。

### 2. 做法：抽硬事实，逐条回原文核对

思路一句话：**不核全句，只核"硬事实"**——数字、时间点、处分类别这类"变了就是错"的东西。

```
模型回答 ──抽事实──> [0.10元, 23:30, 留校察看] ──逐条 contains──> 被引用块的原文
                                                        │
                                              找不到 → missingFacts（红灯）
```

#### 2.1 抽什么（`AnswerGuard.extract`）

| 类型 | 正则 / 词表 | 例子 |
|---|---|---|
| 数字 + 单位 | `\d+(?:\.\d+)?\s*(?:学时\|学分\|元\|天\|个月\|年\|瓦\|册\|个工作日\|工作日\|%)` | `0.10元`、`51学时`、`1500瓦` |
| 时间点 | `\d{1,2}:\d{2}` | `23:30` |
| 处分类别 | 词表 `严重警告 / 警告 / 记过 / 留校察看 / 开除学籍` | `记过` |

**不抽**"每册每日"、"缴清前暂停借书"这类软表述——模型换个说法意思一样，硬核会全是假警报。

#### 2.2 比对前先归一化（`AnswerGuard.normalizeDigits`）

同一个数有好几种写法，不归一化就会误报：

| 原写法 | 归一化后 | 处理 |
|---|---|---|
| `0.10元` | `0.1元` | 去掉小数末尾多余的 0 |
| `０.１０ 元` | `0.1元` | 全角转半角 + 去空格 |
| `1500 瓦` | `1500瓦` | 去掉数字与单位间空格 |
| `1000元` | `1000元` | **整数里的 0 不能去**（这就是为什么不能简单 `replace("0","")`） |

一个易踩的坑：Java 的 `\d` 只认半角。所以 `extract()` 里也要先做一次全角→半角，否则 `０.１０` 连正则都匹配不到，会被当成"没有事实"直接放过。这个坑是单测 `fullWidthAndSpaces` 抓出来的。

#### 2.3 结果怎么用

`QaAnswer` 增加三个字段：

| 字段 | 含义 |
|---|---|
| `grounded` | `missingFacts` 是否为空（true = 抽出来的事实都能在引用原文里找到） |
| `factCount` | 抽到几条可核对事实（`0` 表示这段回答里没有硬事实，无从核对，前端显示"无可核对事实"而不是"通过"） |
| `missingFacts` | 对不上的事实清单，UI 悬停可看 |

前端第三枚徽章（`static/index.html`）：

- 绿：`11 个事实已核对`
- 黄：`2 个事实与原文不符`（title 里列出是哪两个）
- 黄：`无可核对事实`（factCount=0）

### 3. 实测

`POST /api/qa {"question":"旷课多少学时会被处分？","topK":3}`（8090，真调 DeepSeek）：

```
grounded     = true
factCount    = 11
missingFacts = []
citationOk   = true
topScore     = 0.9798
elapsedMs    = 2526
```

回答里 11 个学时分档（20/21-30/31-40/41-50/51）与三档处分全部与原文一致。

单测覆盖 6 种情形（`AnswerGuardTest`，`mvn test -Dtest=AnswerGuardTest` → 6/6 绿）：

| 用例 | 断言 |
|---|---|
| `allFactsPresent` | 0.10 元与原文一致 → 可信 |
| `wrongNumberCaught` | 0.20 元原文没有 → 必须抓出来 |
| `trailingZeroEquivalence` | 0.1 ≡ 0.10 → 不误报 |
| `fullWidthAndSpaces` | 全角 `０.１０ 元` → 不误报 |
| `punishmentNames` | 「开除学籍」原文没有 → 抓出来 |
| `factInAnyCitedChunk` | 事实出现在任一被引用块里 → 命中 |

### 4. 它挡不住什么（局限，写论文要老实说）

1. **子串误判**：`contains("警告")` 对原文「严重警告」也成立 → 短词命中长词，可能漏报。彻底解决需要词语边界或结构化比对。
2. **只核硬事实，不核语义**：模型把「不得」改写成「禁止」不会报错——这是对的（意思没变），但也意味着**语义层面的编造抓不到**。
3. **事实被切分劈开时**：若某个数字在相邻块而模型只引用了一块，会误报。目前靠「精排+展开邻居」把相邻块内容带进上下文缓解。
4. **不核"是否回答了问题"**：接地校验只看"说的有没有依据"，不管"有没有答到点子上"。答非所问但每句都有出处，仍然会判绿。

所以完整的防幻觉是**五道防线**（见 `docs/01-原理大纲.md` 与工作日志）：
语料完整 → 检索捞得回来 → 提示词约束 → **接地校验** → 产品层（引用原文 + 阈值拒答 + "以正式文件为准"）。

## 两段式生成（先摘原句再作答）

> 出处：原 `docs/16-两段式生成.md`（已合并，正文未改写）

> 2026-11-22 晚。起因：badcase 分类发现 46 道答不好的题里 **30 道（65%）是"正确块已经在 Top3、模型还是编细节"**。
> 这一节记录"把找和写拆开"的实验、结果，以及为什么最后**默认关闭**。

### 1. 做法

单段式（原来）：

```
资料 3 块 + 问题  →  DeepSeek  →  答案（边找边写）
```

两段式：

```
第 1 步：资料 3 块 + 问题  →  DeepSeek  →  JSON：[{"n":1,"quote":"资料原句"}]
第 2 步：问题 + 上面摘出的原句  →  DeepSeek  →  答案（只能用这些原句）
```

关键设计：

| 设计 | 理由 |
|---|---|
| 第一步要求**逐字复制** | 它一旦开始"总结"，就会顺手补常识 |
| 服务端用 `looseContains` 再核一遍 | 摘出来的句子必须能在对应块里找到（忽略空白与标点），否则丢弃——防止它"引用"自己编的句子 |
| 第一步输出 JSON 数组 | 便于程序校验；解析失败就回退单段式 |
| 第二步上下文只放原句（通常 <200 字） | 比 3 块全文（约 720 字）更省 token、干扰更少 |
| 证据不足时允许说"未收录" | 否则它会为了不拒答而编 |

代码位置：`PromptBuilder.buildExtractMessages / buildAnswerMessagesFromQuotes`、`QaService.extractQuotes`、
`LlmProperties.twoStage`、`application.yml` 的 `campus.llm.two-stage`。

### 2. 实测（120 题，118 应答题，同一台机、同一时间窗）

| 指标 | 硬化+阈值（上一版） | **两段式** | 变化 |
|---|---|---|---|
| 严格正确率 | 51.7% | **51.7%** | 0 |
| 宽松（正确+部分） | 78.8% | 79.7% | +0.9pt |
| 幻觉题数 | 41（34.7%） | **37（31.4%）** | **-3.3pt** |
| 误拒 | 6（5.1%） | **11（9.3%）** | **+4.2pt** |
| 答案长度 | 123 字 | 约 130 字 | 持平 |
| 延迟 | 1.39s | **2.05~2.40s** | +0.6~1.0s |

按题型：数值型 21/29 正确（上一版 18）、硬改写 9/30（上一版 9）、事实型 18/27（上一版 16）、流程型 4/13（上一版 5）。

### 3. 诚实结论：净收益为零，**默认关闭**

1. **幻觉降了 3.3pt，误拒涨了 4.2pt，严格正确率一点没动。**
   等于把"编一个错答案"换成了"拒答"——对用户不一定是坏事，但对"答对率"这个指标是零和。
2. **误拒为什么涨**：第二步的证据通常只有 1~3 句，覆盖面比整块全文窄。
   原来整块里"顺带"能读到的条文，现在没进证据 → 模型按规则说"未收录"。
   #99（工资标准）、#108（困难证明）、#120（补考次数）都是这个原因。
3. **延迟涨 0.6~1.0s**：多一次模型调用。演示时 2.4s 也能接受，但这笔账要一起算。

所以：**代码保留、默认关闭**（`campus.llm.two-stage: false`），
需要时用 `--campus.llm.two-stage=true` 打开，用于论文里"两段式 vs 单段式"的对照实验。

### 4. 这个实验仍然有三点价值

1. **它证明了"加料"不是提示词能解决的**——约束再严，只要模型是在"边找边写"，它就会补。
   要彻底解决得让它"只抄不写"，而只抄又会拒答变多。这是一个真实的两难，不是工程疏忽。
2. **它给了论文一个诚实的负结果**：与"自适应权重"一样，属于"做了、测了、没用，如实记录"。
3. **它暴露了真正的杠杆在证据覆盖宽度**：如果第一步能摘到 5~8 句（而不是 1~3 句），
   拒答就会降下去。这指向一个明确改法：**第一步按"整块的条"摘，而不是按"句子"摘**（下一步候选）。
