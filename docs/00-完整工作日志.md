## 阶段二 · 技术验证实验（2026-11-05）

目的：**在写系统之前，先把每个技术点单独验证一遍**，确认它们真的能跑、参数怎么定。

### 实验 1：Python 版 RAG 演示（`labs/rag-demo-python/rag_demo.py`）

- 纯标准库实现，约 200 行；函数 `load_documents / split_into_chunks / embed_offline / embed_online / cosine / retrieve / build_prompt / chat_online`
- 自造 2 份校园规章样例；哈希向量 512 维；`CHUNK_SIZE=220 / OVERLAP=50 / TOP_K=3`
- **实测**：5 道测试题在 Top-3 内的关键词命中数 = **4/5**（切分 220/50），切成 150/30 时掉到 3/5
- 发现一个真问题：**短查询 vs 长段落的余弦存在长度偏置**，「宿舍能用大功率电器吗」的正确块进不了 Top-3

### 实验 2：Java 版（`labs/rag-java/`）

- `Chunk` / `TextSplitter`（句末回退）/ `Tokenizer`（单字 + 双字 bigram）/ `HashEmbeddingModel`（512 维）
- `VectorIndex`（点积）/ `Bm25Index`（K1=1.5, B=0.75）/ `Retriever`（RRF，`RRF_K=60`）
- **实测**（220/50，16 块）：向量 4/5、BM25 5/5、混合 5/5
- 跨语言验证：和 Python 版块数一致（16 块），说明切分逻辑两边一致

### 实验 3：文档解析（`labs/tika-lab/`，Tika 3.3.3）

| 文件类型 | 字符 | 关键词命中 |
|---|---|---|
| docx | 531 | 3/3 |
| 正常 PDF | 192 | 2/2 |
| **扫描件 PDF** | **0** | 0/1 |
| txt | 161 | 2/2 |
| 缺 ToUnicode 的 PDF | 15 | 0/1 |

**三个真发现**：
1. **扫描件 PDF**（只有图片没文本层）→ 必须 OCR
2. **缺 ToUnicode 映射的 PDF** → 人看得见、机器抠不出，只能拿到 ASCII 碎片
3. **docx 表格能提取但列关系丢失** → `10-19 学时 警告 由学院处理` 被压成一行

### 踩坑

`类文件具有错误的版本 55.0, 应为 52.0` = Maven 跑在 JDK 8 上；Tika 3.x 的常量迁到了 `TikaCoreProperties` / `HttpHeaders`；日志需要 `log4j-slf4j2-impl`。

## 阶段四 · 检索消融实验（2026-11-18）

这是**唯一一段"能写进论文"的核心实验**，也是被自己推翻过的一段。

### 建评测管线

- `data/raw/`：9 篇虚构校园规章（7965 字，49 块 @220/50）
- `data/testset/eval_questions.tsv`：TSV 格式（id / 问题 / 关键词 / 题型 / 难度）
- `EvalRunner.java`：读外部语料 + 题集，输出 Recall@K / MRR / 平均延迟 / 按题型拆解

### 46 题时的结果（第一次）

| 方案 | MRR | Recall@3 |
|---|---|---|
| 纯向量 | 0.8395 | 0.89 |
| BM25 | 0.9348 | 0.96 |
| 混合 RRF（等权） | 0.8949 | **1.00** |
| 加权 RRF（0.2/0.8） | 0.9384 | 1.00 |
| 加权 + 重排 | **0.9457** | 1.00 |
| 单信号重排 | — | 变好 0，变差 5（负结果） |

当时结论：混合把召回拉满，重排再提 MRR。

### 然后自己打脸：题集扩到 70 题

新增 16 道**改写型**（提问用同义词）+ 8 道**多跳型**（要组合同一条内两个信息点），并且自动校验"每个关键词都在语料中出现"。

| 方案 | MRR | Recall@3 |
|---|---|---|
| 纯向量 | 0.8073 | 0.86 |
| BM25 | 0.9296 | 0.96 |
| 混合 RRF（等权） | 0.8705 | 0.97 |
| **加权 RRF（0.2/0.8）** | 0.9249 | **0.99** |
| 加权 + 重排（默认权重） | 0.9059 | 0.96 |

**三个反转**：

1. **重排从"有用"变"有害"**：网格搜索最优是 `w(覆盖率)=0, w(向量)=0`，即"完全不重排"。坏掉的题全是改写型——重排靠字面覆盖率，而改写型最怕字面不一致
2. **结构切分「一条一块」从满分跌到 0.93**：块太小（均 67 字），丢上下文
3. **唯一漏题暴露同义词死穴**：问「想换专业成绩要达到什么标准」，正确块排到第 **13** 名（"换专业" vs 原文"转专业"）→ 字面检索无解，必须真 Embedding

### 写进论文的三个结论

1. **题集小的时候几乎什么方法都有效**——这是小样本假阳性，必须扩题集
2. 调参必须在验证集上，结论只能写"在本文构建的 N 道题集上"
3. **主动记录"结论反转"就是科研诚信证据**，答辩时是加分项

产出：`docs/06-评测方法与基线实验.md`（370+ 行，10 节）+ `StructuredSplitter` + `Reranker` + 70 题题集

结论：4 个变好，1 个仍漏 → **不是语料问题，是检索方式问题**。

### 六、被证实的两个判断

1. **「旷课多少学时」不是幻觉，是语料真缺**
   - 学籍管理规定（54 条完好）里**一次都没出现"旷课"**
   - 违纪处分条例第二十二条写"按《学籍管理规定》执行"——指了个空
   - 真正写了学时标准的是《学生考勤与请假管理办法》，**我们没有这份**
2. **RAG 项目里"写代码"只占一半，另一半是数据工程**——OCR 这段占了两小时，不产生一行系统功能

| # | 经验 | 出处 |
|---|---|---|
| 1 | 切分要按**句子边界**回退，且回退要有下限（`size*0.65`），否则"回退+重叠"双重缩短把块切碎 | 748→305 块 |
| 2 | PDF 的**换行不是句子边界**，必须先删掉再切 | 平均块长 99→195 |
| 3 | 切完要**过滤/合并超短块**（<10 字），否则污染检索 | 最短块 1→132 |
| 4 | Embedding 返回的 `data[]` **顺序不保证**，要按 `index` 排序 | 向量化实现 |
| 5 | 向量必须**统一归一化**，点积才等于余弦 | 两处实现都做了 |
| 6 | 换 embedding 模型/切分参数后，旧向量**静默失效** → 要存 `config_hash` 做指纹校验 | 参考项目设计 |
| 7 | 纯向量对**列举型/数字型**查询弱，BM25 补位；RRF 融合要**按路加权**（我们 0.2/0.8） | 70 题消融 |
| 8 | 重排不是万能的，**靠字面覆盖率的重排对改写型是负收益** | 46→70 题反转 |
| 9 | 扫描件必须 OCR；缺 ToUnicode 的 PDF 人看得见机器抠不出 | Tika 实验 + 12 份 OCR |
| 10 | 幻觉只能"降低 + 可发现"，引用校验要从"编号越界"升级到"内容溯源" | 引用造假案例 |
