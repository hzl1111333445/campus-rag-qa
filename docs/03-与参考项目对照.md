## 主对照表：它有的模块 ↔ 我们的类

| 环节 | xunqian99 的实现 | 我们（本项目） | 状态 | 差异说明 |
|---|---|---|---|---|
| 上传接口 | `document/controller` | `controller/DocumentController` | ✅ | 一致：multipart 存盘 + 建记录 |
| 文档解析 | LangChain4j DocumentParser | `service/DocumentParser`（Tika 3.3.3） | ✅ 实测：真实 PDF 7969 字 | 我们多做了"扫描件检测"（<50 字直接报错） |
| 文本切分 | 按标题层级 + `max-size=120, overlap=0` | `service/TextSplitter`（滑动窗口+句末回退，220/50） | 🟡 能切，但**平均只有 100 字，需修** | 它按 Markdown 标题切所以不需要 overlap；我们的语料是 PDF 纯文本，只能按长度切 |
| 块入库 | pgvector 里带向量 | `kb_chunk` 表（MySQL，暂不存向量） | ✅ 实测 84 块 | 我们把"块"和"向量"分两步走，先纯文本通了再加向量 |
| 向量化 | LangChain4j EmbeddingModel | 待写 `EmbeddingClient` | ⬜ | 计划：真模型（bge-m3）与"哈希假向量"两个实现，可切换对比 |
| 向量存储 | pgvector 类型 + 索引 | MySQL `LONGTEXT` 存 JSON 数组 | ⬜ | 取舍：不用装额外中间件；代价是全表扫描，语料小可接受 |
| 检索·向量路 | pgvector 余弦 | 待写（Java 里算余弦） | ⬜ | 已在 `E:\tmp\ai\labs\rag-java` 验证过 |
| 检索·关键字路 | **Elasticsearch 8.15** BM25 | 待写 `Bm25Index`（手写，无依赖） | ⬜ | 它上 ES；我们用 60 行 Java 实现 BM25，**面试可讲公式** |
| 融合 | RRF（k=60） | 待写 `RrfFusion` | ⬜ | 公式一样：`1/(k+rank)` 求和 |
| 精排 | Cross-Encoder 模型 | 待写 `Reranker`（可用硅基流动 API） | ⬜ | 没 key 时设计成"降级为 RRF 顺序"而不是报 500 |
| 问答生成 | LLM + 提示词约束 | 待写 `AnswerGenerator` | ⬜ | 计划：mock（摘录式）/ 真 LLM 双实现，无 key 也能演示 |
| 引用溯源 | 返回 sources 数组 | 待写 `qa_message_ref` 表 | ⬜ | 我们的做法更硬：**回答里的 `[n]` 编号要做合法性校验**，编造的编号能被发现 |
| 流式输出 | SSE（meta→delta→done） | 待写 `QaController#askStream` | ⬜ | 我们的协议多一个 `refs` 事件，先发来源再发正文 |
| 会话记忆 | Redis + 最近 N 轮 | 计划：直接查 `qa_message` 表 | ⬜ | 不引入 Redis（少一个依赖，也是取舍点） |
| 评测 | 150 题，Recall@K/MRR | `E:\tmp\ai\data\testset` 已有 70 题 | ⬜ 未接入 | **这是我们比它扎实的地方**：题集人工标了关键词，还分事实/数值/流程/改写/多跳五类 |
| 前端 | Vue3 + Vite + Tailwind，4 个组件 | 待做 | ⬜ | 计划 Vue3 + Element Plus（你更熟这个） |
| 部署 | docker-compose 一键 | 待做 | ⬜ | 计划：本地一键脚本 + 一台云服务器 |
| 缓存 | Redis 缓存检索结果 | **决定不做** | — | 理由：语料只有几十篇，缓存收益不明显，还多一个故障点 |

## 我们要抄它的三件事（不是代码，是做法）

1. **决策日志**：它 `docs/decisions.md` 有 27 条，每条 7 栏（做了什么/为什么需要/关键决策/备选方案与放弃原因/踩到的坑/验证结果/面试可能被追问）。
   → 我们每完成一个环节，就在 `docs/决策日志.md` 里补一条。
2. **参数都有出处**：它的 `rrf-k=60`、召回 50、精排候选 20、最终 3 都写在哪来的。
   → 我们的 220/50 也要能说清"怎么试出来的"（`E:\tmp\ai` 里有对照实验数据）。
3. **确定性排序**：同分时按 chunkId 兜底。它注释写得很准——"不确定的结果会让'改了什么导致效果变化'无法分析"。

## 我们故意不抄的三件事

| 不抄 | 原因 |
|---|---|
| LangChain4j 现成封装 | 面试问"RRF 怎么算"、"切分为什么要有 overlap"，能自己写才答得上 |
| pgvector / ES / Redis / Docker | 你机器没有 Docker；每题都装一个中间件，学习曲线会崩 |
| WebFlux 响应式 | 先把同步阻塞版写对，响应式是性能优化，不是第一天的功课 |
