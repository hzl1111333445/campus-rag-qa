# 拒答阈值（E 方案）：资料不够就别问大模型

> 记录时间：2026-11-22 晚
> 代码：`RetrievalService.searchBestGated()` / `Best` 记录；`QaService.ask()` 的闸门分支；`SearchController` 的 `mode=best`
> 标定脚本：`tools/calibrate_threshold.py`
> 配置：`campus.retrieval.min-score-rerank`（默认 0.10）、`campus.retrieval.min-score-hybrid`（默认 0，未启用）

---

## 一、要解决什么问题

E 方案之前，库里根本没有的问题（「食堂几点开门」「图书馆能借几本书」）也会走完整条链路：

```
向量化 → 混合检索 → 精排 → 拼提示词 → 调 DeepSeek → 模型靠提示词说"暂未收录"
```

两个坏处：

1. **白花钱**：明知道资料不相关，还是调了一次大模型（约 1.3 秒 + 一次 token 费用）
2. **多一次编造机会**：模型手里有 3 个不相关的块，提示词只能"劝"它别用，劝不住就编

正确做法：**在检索层就判断"资料够不够"**，不够就直接回话，不问模型。这叫"宁可说没查到，也不猜"。

---

## 二、怎么判断"够不够"——用哪个分数

系统里有两个分数，**量纲差 20 倍，绝不能共用一个阈值**：

| 分数 | 量级 | 说明 |
|---|---|---|
| 精排分（Cross-Encoder） | 0 ~ 1，真能答上来的常见 0.5~0.99 | 「问题 + 这一段」一起送进模型，输出"这一段能回答这个问题的概率" |
| 混合 RRF 分 | 0.0x（两路都排第一也只有 0.0328） | Σ 权重/(60+名次)，只反映"名次好不好"，不反映"内容对不对" |

所以我们配两个：

```yaml
min-score-rerank: 0.10    # 开精排时用这个（当前生效）
min-score-hybrid: 0.0     # 关精排时用这个（还没标定，先不启用）
```

---

## 三、标定：36 道题 + 8 道探针，用数据定阈值

### 方法

```powershell
python tools\calibrate_threshold.py 8090   # 逐题调 /api/search?mode=best，取 topScore
```

脚本做三件事：逐题取最高分 → 按"可答 / 库里没有"两组排序 → **扫描 0.20~0.65 每个阈值会误拒几道、放过几道**。

### 实测分布

| 组 | 题数 | 分数范围 |
|---|---|---|
| 可答题 | 32 | 最低 **0.2004**（#29 毕业要修满多少学分），最高 0.9976 |
| 库里没有（题集里的 4 道） | 4 | 最高 **0.0025**（#35 食堂几点开门），最低 0.0016 |

**两组之间有 80 倍的间隔**，说明精排分是真的能区分"有没有资料"，不是玄学。

### 阈值扫描

| 阈值 | 误拒（可答题被判没资料） | 放过（无答案题混进来） |
|---|---|---|
| 0.20 | 0 | 0 |
| 0.25 | 3 | 0 |
| 0.40 | 3 | 0 |
| 0.55 | 6 | 0 |
| 0.65 | 9 | 0 |

**结论：取 0.10**。
理由：0 误拒、4 道无答案题全拦；离可答题最低分（0.2004）还有 0.10 的安全余量，语料扩充后不容易误伤。
取 0.20 也能 0 误拒，但离边界太近——样本只有 32 道，边界值随时会被新题打破。

## 四、8 道"探针题"：暴露了阈值的真实边界

标定时我额外问了 8 个题集里没有的问题，看分数落在哪：

| 问题 | 精排分 | 闸门 | 实际情况 |
|---|---|---|---|
| 图书馆开放时间是什么 | 0.0030 | 🚫 拦 | 库里确实没有 ✅ |
| 食堂一顿饭多少钱 | 0.0031 | 🚫 拦 | 库里确实没有 ✅ |
| 宿舍楼晚上几点关门 | 0.0023 | 🚫 拦 | 库里确实没有 ✅ |
| 宿舍可以用电吹风吗 | 0.0117 | 🚫 拦 | 库里确实没有 ✅ |
| 晚上超过门禁时间回宿舍怎么办 | 0.0511 | 🚫 拦 | 库里确实没有 ✅ |
| 学生证补办要多少钱 | 0.1435 | ✅ 放 | 规定里写了"需缴纳工本费"但没写金额 → 该放行，让模型说"没写金额" |
| 补考还不及格怎么办 | 0.4411 | ✅ 放 | 学籍规定里有重修条款 → 该放行 |
| **旷课多少学时会被处分** | **0.8929** | ✅ 放 | ⚠️ 库里**没有**学时标准（原文指向一份我们没收的文件）→ **分数闸门拦不住** |

### 这一行是重点，也是局限

「旷课多少学时」拿到 0.89 分，因为库里有大量"旷课""处分"相关内容，只是**具体数字没有**。
分数闸门只能判断"主题在不在库里"，判断不了"具体那条答案在不在库里"。

所以拒答是**两层**的：

| 层 | 管什么 | 我们的做法 |
|---|---|---|
| 检索层（本方案） | 主题都不在库里 → 不问模型 | 精排分 < 0.10 直接拒答 |
| 生成层（已有） | 主题在、细节缺 → 让模型说"没写" | 提示词第 2/6 条 + 收录范围清单 |

## 五、验证（8090 实测）

| 问题 | 耗时 | gated | 结果 |
|---|---|---|---|
| 食堂几点开门 | **0.44s** | true | 「本知识库暂未收录…（检索置信度不足，最高相关度 0.0024，低于阈值 0.1）」+ 0 条引用 |
| 宿舍可以用电吹风吗 | **0.39s** | true | 同上（0.0115 < 0.1） |
| 转专业名单公示期不少于几天 | 1.72s | false | 「不少于 5 个工作日」+ 3 条引用 [1][2][3] |

**收益**：被拦下的问题从 1.7 秒降到 0.4 秒（省掉一次大模型调用），并且不再产生任何引用卡片。

响应里新增两个字段，前端可以直接用来显示"这条是拒答，不是答案"：

```json
{ "answer": "...", "topScore": 0.0024, "gated": true, "references": [], "elapsedMs": 440 }
```

## 六、局限（写论文时必须写）

1. **样本量**：32 道可答题 + 4 道无答案题 + 8 道探针，阈值边界（0.10）是经验值，不是统计结论。
2. **只能挡"主题不在库里"**：主题在、细节缺（旷课学时、具体金额）挡不住，要等 groundedness 校验。
3. **换 embedding 模型或改切分，精排分的分布会变**，阈值必须重新标定（脚本已经能一键跑）。
4. **关掉精排时**（`campus.rerank.enabled=false`）走 `min-score-hybrid`，那个阈值还没标定，默认 0 = 不启用，属于已知缺口。
5. 拒答话术里把阈值和分数暴露给了终端用户（方便调试），**正式上线应改成对用户友好的说法**，把分数写日志而不是写回答。

- 阈值 0.10 仍然站得住：仍会拦下食堂、宿舍、校医院三类问题

**新发现的边界问题（已知局限）**：
「图书馆几点开门」这类**问短文档的问题**，精排分只有 0.0581~0.1051，在阈值 0.10 附近抖动 → 同义改写成不同问法时会误拒。
处理：暂不下调阈值（下调会放过食堂 0.1788），改为在拒答文案里提示"可以换一种问法重试"。
若要根治，两条路：① 把短文档合并进一份长文档（块更完整、分数更稳）② 加查询改写（先用大模型把问题扩写成规则文本再检索）。
