# 33 · 可观测性：指标、健康检查与"谁能看"

> 本篇记录 `/actuator` 接入过程与三个实测踩到的坑。代码位置：
> `demo/src/main/java/com/campus/rag/config/MetricsConfig.java`、
> `demo/src/main/java/com/campus/rag/service/BusinessMetrics.java`、
> `demo/src/main/java/com/campus/rag/config/ActuatorGuardFilter.java`。

## 一、为什么加指标

在这之前，系统只有**单次请求**的 `elapsedMs`。它回答不了三个问题：

1. 最近一小时 P95 是多少？（面试常问）
2. 拒答率、缓存命中率、精排降级次数各是多少？
3. 线上变慢时，是模型慢了、检索慢了，还是数据库慢了？

指标就是把这些"只能靠感觉"的东西变成可查询的时间序列。

## 二、分了两层：自动 + 业务

| 层 | 来源 | 内容 |
|---|---|---|
| 自动（HTTP） | Actuator 自带 `http_server_requests_seconds` | 每个 URI 的 QPS、P50/P95/P99、状态码分布 —— **不用自己埋点** |
| 业务 | `BusinessMetrics` | 问答次数（按 `mode`/`gated`/`cached`）、问答耗时、检索层拒答、缓存命中、精排降级、Agent 结局与步数 |
| 数据规模 | `MetricsConfig` 的 Gauge | 文档数、块数、已向量化块数（三者差值 = "搜不到"的量） |

暴露方式：`/actuator/prometheus`（Prometheus 文本格式），可直接接 Grafana。

## 四、三个坑（都踩了，且都不报错）

### 坑 1：`WebMvcConfigurer.addInterceptors` 拦不住 `/actuator/**`

第一版用 `HandlerInterceptor` 保护 `/actuator/**`，结果**无令牌照样 200**。
原因：Actuator 的端点由 Spring Boot 自己注册的一套 handler mapping 处理，
`WebMvcConfigurer` 注册的拦截器对它不生效。

修法：改成 Servlet 层的 `OncePerRequestFilter`（`ActuatorGuardFilter`），
`shouldNotFilter` 里放行 `/actuator/health`，其余校验 `Authorization: Bearer` 并判角色。
**教训：安全要放在"请求必经之路"上，而不是某个框架的扩展点里。**

### 坑 2：Gauge 用弱引用，对象被 GC 后指标静默消失

```java
// 错误写法：CachedNumber 实例没有强引用，GC 后 gauge 就没了
Gauge.builder("campus_documents", new CachedNumber(dao::count)).register(registry);
```

Micrometer 对 Gauge 的观测对象是**弱引用**。表现是 `/actuator/metrics` 里查不到、也不报错。
修法：把 `CachedNumber` 存成 `MetricsConfig` 的 final 字段（强引用），
`Gauge.builder(name, field)` 再注册。

### 坑 3：名字以 `_total` 结尾的 Gauge 会被 Prometheus 改名

Gauge 原名 `campus_documents_total`，Prometheus 导出成了 `campus_documents`
（`_total` 是 Counter 的保留后缀）。按原名 grep 会以为"指标没出来"。
修法：Gauge 统一用 `campus_kb_*` 前缀，不在名字里用 `_total`。

## 五、标签基数：别把问题原文当标签

允许的标签只有有限枚举：`mode ∈ {sync, stream, agent}`、`gated ∈ {true,false}`、
`cached ∈ {true,false}`、`result ∈ {hit, miss}`、`reason`（降级原因）。

**绝不能**把 `question`、`userId`、`sessionId` 当标签——每个不同的值都会生成一条独立时间序列，
几千次提问就能把 Prometheus 打爆。需要看具体问题时查 `qa_message` 表，不要查指标。

## 六、面试怎么说（30 秒）

> "监控分两层：HTTP 层用 Actuator 自带的 `http_server_requests`，直接有 QPS、P95 和状态码分布；
> 业务层我自己加了 `BusinessMetrics`，记录问答次数（按同步/流式/Agent 和是否命中缓存、是否被拒答打标签）、
> 检索层拒答率、缓存命中率、精排降级次数，还有三个 Gauge 反映知识库规模。
> `/actuator/prometheus` 给 Prometheus 抓，但只对管理员开放——health 公开、其余 401/403。
> 过程中踩了两个不报错的坑：Gauge 弱引用被 GC、`_total` 后缀被 Prometheus 改名。"

## 七、已知局限

- 没有接 Grafana / Prometheus 服务端（本机只有一个 `/actuator/prometheus` 文本端点），
  所以"看板"这一层还没做；面试时如实说"指标已埋，可视化没接"
- `campus_qa_tokens_total` 只统计成功问答的 token，拒答路径记 0（因为确实没调模型）
- 指标刷新有 30 秒缓存（Gauge），不是实时值
