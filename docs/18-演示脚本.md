# 3 分钟演示脚本

> 用途：面试前把这段录成视频，或面试时共享屏幕现场演示。
> 原则：**每一屏只讲一句"为什么"，数字全部来自真实评测，不吹没做过的事。**

## 一、录制前准备（10 分钟）

1. **起服务**（单 jar，不依赖 IDE）：
   ```powershell
   cd E:\tmp\campus-ai-rag
   .\start.ps1 -Port 8081
   ```
   看到 `==> 就绪` 即可；地址 `http://localhost:8081/`。
2. **登录**：用 `admin / admin123`（管理员，能看全部页面）。学生账号留到最后一句提"角色不同看到的菜单不同"。
3. **确认三件事**：
   - `/api/health` 是 `UP`
   - 文档管理里是 **33 份 / 643 块**（数字对不上说明语料没导）
   - 检索调试里问一句能出五路结果（依赖精排接口可用）
4. **录屏设置**：1920×1080、浏览器 100% 缩放、关掉微信/QQ 弹窗、麦克风离嘴 15cm。
5. **禁止出现**：真实的 API Key、`application-local.yml`、数据库密码、桌面上的简历文件。

## 二、分镜（总 180 秒）

| 时间 | 画面 | 说什么（口语版） | 为什么这么讲 |
|---|---|---|---|

## 四、三个必讲的"我做过但没做成"

1. **自适应融合权重**：想法是"BM25 信号弱就加大向量权重"，线上实测只多对 1~2 道，dev 集零变化 → 默认关闭。
2. **两段式生成**（先摘原文句子、再只用原句组答案）：幻觉 34.7%→31.4%，但误拒 5.1%→9.3%、延迟 1.4s→2.1s，答对率没涨 → 默认关闭，开关留着。
3. **"把模型答案写进向量库"**：被自己否掉——那是用模型输出去洗模型输入，且会污染评测。

> 讲这三件事的正确姿势："我做了，数据不支持，所以我关掉了，开关还在。" —— 这一句比任何功能都能证明会做研究。

## 五、常见追问与答法

**Q：为什么不直接用 LangChain / Spring AI？**
A：这层抽象省的是 adapter 胶水，我在 300~500 行里手写了调用与解析，换来的是能说清每一步。真正值得引入的是 Agent 工具调用与 tracing，那是下一步。项目里一行 LangChain 都没有（可以现场 `pom.xml` 给你看）。

**Q：51.7% 正确率是不是太低？**
A：严格口径（必须答全）51.7%，含部分正确 78.8%。剩下 42 个点的损耗我拆过：检索 9.3 个点、答案加料 32.2 个点、误拒 5.1 个点、真错 5.1 个点。所以主战场在生成层，不在检索。

**Q：多轮怎么做的？**
A：两层。历史进生成层做指代理解（带 3 轮、单条截 120 字、总量 600 字、抹掉历史里的引用编号防止抄错）；追问时先用原句检索，分数低于阈值才做"追问补全"再检索一次，**只有补全后分数更高才采用**。8 组追问对照：单轮 Top1 正确率 38% → 带历史 100%（样本小，只当方向性证据）。

**Q：8 组也算实验？**
A：不算结论，算方向。要下结论至少 30 组，这条我写在文档的"已知局限"里。

**Q：数据隔离 / 权限怎么做的？**
A：会话归属写在 `qa_session.user_id` 里，判定压成一个纯函数 `SessionAccess.can(owner, requester, isAdmin)`；越权一律返回"会话不存在"而不是 403，避免泄露 id 存在性。机器调用（评测脚本）走 `X-No-Persist` 头显式旁路，不写对话历史。

**Q：为什么不用向量数据库？**
A：643 块、1024 维，MySQL 里存 JSON 数组 + 内存暴力算余弦就够了，单次检索几十毫秒。Milvus/pgvector 是为百万级准备的，现在引入只是给自己加部署负担——这条也写在 README 的"已知局限"里。
