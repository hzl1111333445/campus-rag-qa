# 两段式生成（先摘原句，再组答案）

> 2026-11-22 晚。起因：badcase 分类发现 46 道答不好的题里 **30 道（65%）是"正确块已经在 Top3、模型还是编细节"**。
> 这一节记录"把找和写拆开"的实验、结果，以及为什么最后**默认关闭**。

## 1. 做法

单段式（原来）：

```
资料 3 块 + 问题  →  DeepSeek  →  答案（边找边写）
```

两段式：

```
第 1 步：资料 3 块 + 问题  →  DeepSeek  →  JSON：[{"n":1,"quote":"资料原句"}]
第 2 步：问题 + 上面摘出的原句  →  DeepSeek  →  答案（只能用这些原句）
```

关键设计：

| 设计 | 理由 |
|---|---|
| 第一步要求**逐字复制** | 它一旦开始"总结"，就会顺手补常识 |
| 服务端用 `looseContains` 再核一遍 | 摘出来的句子必须能在对应块里找到（忽略空白与标点），否则丢弃——防止它"引用"自己编的句子 |
| 第一步输出 JSON 数组 | 便于程序校验；解析失败就回退单段式 |
| 第二步上下文只放原句（通常 <200 字） | 比 3 块全文（约 720 字）更省 token、干扰更少 |
| 证据不足时允许说"未收录" | 否则它会为了不拒答而编 |

代码位置：`PromptBuilder.buildExtractMessages / buildAnswerMessagesFromQuotes`、`QaService.extractQuotes`、
`LlmProperties.twoStage`、`application.yml` 的 `campus.llm.two-stage`。

## 2. 实测（120 题，118 应答题，同一台机、同一时间窗）

| 指标 | 硬化+阈值（上一版） | **两段式** | 变化 |
|---|---|---|---|
| 严格正确率 | 51.7% | **51.7%** | 0 |
| 宽松（正确+部分） | 78.8% | 79.7% | +0.9pt |
| 幻觉题数 | 41（34.7%） | **37（31.4%）** | **-3.3pt** |
| 误拒 | 6（5.1%） | **11（9.3%）** | **+4.2pt** |
| 答案长度 | 123 字 | 约 130 字 | 持平 |
| 延迟 | 1.39s | **2.05~2.40s** | +0.6~1.0s |

按题型：数值型 21/29 正确（上一版 18）、硬改写 9/30（上一版 9）、事实型 18/27（上一版 16）、流程型 4/13（上一版 5）。

## 3. 诚实结论：净收益为零，**默认关闭**

1. **幻觉降了 3.3pt，误拒涨了 4.2pt，严格正确率一点没动。**
   等于把"编一个错答案"换成了"拒答"——对用户不一定是坏事，但对"答对率"这个指标是零和。
2. **误拒为什么涨**：第二步的证据通常只有 1~3 句，覆盖面比整块全文窄。
   原来整块里"顺带"能读到的条文，现在没进证据 → 模型按规则说"未收录"。
   #99（工资标准）、#108（困难证明）、#120（补考次数）都是这个原因。
3. **延迟涨 0.6~1.0s**：多一次模型调用。演示时 2.4s 也能接受，但这笔账要一起算。

所以：**代码保留、默认关闭**（`campus.llm.two-stage: false`），
需要时用 `--campus.llm.two-stage=true` 打开，用于论文里"两段式 vs 单段式"的对照实验。

## 4. 这个实验仍然有三点价值

1. **它证明了"加料"不是提示词能解决的**——约束再严，只要模型是在"边找边写"，它就会补。
   要彻底解决得让它"只抄不写"，而只抄又会拒答变多。这是一个真实的两难，不是工程疏忽。
2. **它给了论文一个诚实的负结果**：与"自适应权重"一样，属于"做了、测了、没用，如实记录"。
3. **它暴露了真正的杠杆在证据覆盖宽度**：如果第一步能摘到 5~8 句（而不是 1~3 句），
   拒答就会降下去。这指向一个明确改法：**第一步按"整块的条"摘，而不是按"句子"摘**（下一步候选）。

## 5. 复现命令

```bash
# 打开两段式
mvn spring-boot:run -Dspring-boot.run.arguments="--server.port=8090 --campus.llm.two-stage=true"
python tools/eval-answer.py && python tools/judge-answers.py && python tools/summarize-answers.py
```
