# 31 · 面试导向的系统性学习计划（对着 JD 补，不背八股）

> 起因：2026-11-25 主人拿「广州讯南网络科技 · Java 后端」JD 说"按面试要求对现有项目做系统性学习"。
> 原则：**每条 JD → 一个能力项 → 一份交付物 → 一句能背的答案（指向真实代码行）**。
> 不做：SpringCloud 全家桶、K8s、多 Agent 平台。做不了的用"取舍 + 边界"回答，不装。

## 一、JD 六条 → 能力项 → 现状 → 缺口

## 二、六个学习模块（每个都是可交付物，不是听课）

### 模块 1 · 业务与事务（半天 ~ 1 天）→ 对 JD 1、3
**做什么**：文档入库任务化改造
- `kb_document` 加 `file_hash`、`retry_count`、`error_msg`、`status` 状态机（0 待处理 / 1 处理中 / 2 成功 / 3 失败 / 4 待重试）
- 上传 → 写任务 → 异步 worker 取任务 → 解析切分 → 写块 → 改状态，**同一事务**（`@Transactional`）
- 幂等：同一 `file_hash` 已存在则拒绝并返回已有文档 id
- 重试：失败 3 次、退避 2s/8s/30s，超限置失败并写 `error_msg`
- 并发：`SELECT ... FOR UPDATE` 或状态机 CAS（`WHERE status=0`）抢占任务

**交付物**：代码 + `docs/32-入库任务化设计.md`（状态机图 + 事务边界 + 幂等键 + 失败矩阵）
**验收**：①重复上传同文件返回 409 且无新块 ②杀掉进程后重启，卡在"处理中"的任务 5 分钟内自动回收 ③故意传坏文件，`error_msg` 可读、状态=失败
**面试答案骨架**：
> "文档入库我改成了任务化：状态机五态、失败重试 3 次带退避、按文件哈希幂等去重；写文档/块/状态放在一个事务里，避免半途失败留下孤儿块。抢占任务用 `UPDATE ... WHERE status=0` 的条件更新做 CAS，不用悲观锁。"

### 模块 2 · MySQL 与索引（半天）→ 对 JD 3
**做什么**：
- 把项目里 4 个 DAO 的 52 处 SQL 过一遍，挑 5 条高频查询做 `EXPLAIN`
- 找一条真慢查询（或人为放大数据量），加索引前后对比 `type/rows/Extra`
- 记录一次"索引失效"现场（比如 `LIKE '%x%'`、函数包列、隐式转换）
- 写一页"慢 SQL 治理流程"：慢日志阈值 → 定位 → EXPLAIN → 改 SQL/加索引 → 回归

**交付物**：`docs/33-SQL与索引实测.md`（5 张 EXPLAIN 截图 + 前后对比表 + 治理流程）
**验收**：能当场对一个陌生查询说出"走不走索引、为什么"
**面试答案骨架**：
> "分页查询我给 `qa_session(user_id, update_time)` 建了联合索引，EXPLAIN 从 `type=ALL rows=42` 变成 `ref`；有一条 `LIKE '%关键词%'` 的前导模糊吃不到索引，我改成全文/前缀匹配。慢 SQL 我先看慢日志再 EXPLAIN，不凭感觉加索引。"

### 模块 3 · Redis 与消息队列（半天）→ 对 JD 3
**做什么**：
- 已有：缓存 + 限流 + 命中率统计。补：**用 Redis List 做一个极简任务队列**（`LPUSH`/`BRPOP`），把模块 1 的 worker 接上去
- 讲清三件事：为什么选 Redis List 而不是 RabbitMQ（单机、无运维、量小）；丢消息怎么办（`BRPOPLPUSH` 到 processing 队列 + 超时回收）；幂等怎么保证（任务 id + 状态 CAS）
- 出一张"缓存/限流/队列 三者键设计"表（前缀、TTL、失效策略）

**交付物**：`docs/34-Redis队列与缓存设计.md`
**验收**：能回答"为什么不用 MQ""消息丢了怎么办""缓存和队列共用一个实例会不会互相影响"
**面试答案骨架**：
> "队列我用 Redis List 的 `BRPOPLPUSH` 做了个可靠版：消费时原子移到 processing 队列，成功后删除，超时未确认的由补偿线程搬回。团队真上量我再换 RabbitMQ，现在单实例足够，我不想为一个功能引入运维成本。"

### 模块 4 · 性能与排障（1 天）→ 对 JD 2、4
**做什么**：
- 压测脚本（Python 并发）：20/50/100 并发，采 QPS、P50/P95/P99、错误率
- 分档压测：只检索（本地快）/ 完整问答（含 LLM，受上游限制）→ **说清"我们的 QPS 被上游卡住"**
- 三档降级演练：关 Redis、关精排、关改写，各跑一次并记录指标变化
- 加 Micrometer 指标（`/actuator/prometheus` 或自定义 `/api/dev/metrics`）：请求数、耗时分布、缓存命中率、LLM 失败数

**交付物**：`docs/35-压测与降级演练.md`（原始数据表 + 瓶颈归因 + 优化前后对比）
**验收**：能说出"瓶颈在哪、占多少、怎么验证"
**面试答案骨架**：
> "压测分两层：检索层 QPS ××、P95 ××ms；整链路受上游 LLM 限制 P95 ××s。降级我做了三档演练，关掉精排召回掉 2pt 但延迟降 300ms。指标我接了 Micrometer，能看每档降级的错误率。"

### 模块 5 · 协作与文档（半天）→ 对 JD 5、6
**做什么**：
- 一页**技术方案模板**（背景/目标/方案对比/取舍/风险/回滚/验收）
- 用模块 1 的入库任务化写一份真方案（当模板样例）
- 一页**代码评审清单**（10 条：事务边界、N+1、异常吞掉、日志级别、幂等、越权、索引、超时、降级、测试）
- 一页**交付节奏表**（排期/依赖/风险/验收人）

**交付物**：`docs/36-技术方案与评审模板.md`
**验收**：能对着任何一次改动填完模板

### 模块 6 · 高可用与微服务叙事（2 小时，只写不实现）→ 对 JD 2
**做什么**：画一张"如果拆，怎么拆"的草图（问答服务 / 文档服务 / 评测服务 / 网关），写清：
- 现在为什么不拆（3 个理由：团队 1 人、调用链短、事务简单）
- 拆的话边界在哪、共享什么（会话表）、怎么保证一致
- 单体下已经做了的"高可用"动作：多级降级、线程池隔离、超时、限流、幂等

**交付物**：`docs/37-单体与拆分取舍.md`（一张图 + 三问三答）
**验收**：被问"你们为什么不用微服务"时能答 60 秒不心虚

## 四、每模块固定四问（写进笔记，也是面试结构）

1. **解决什么问题**（一句话，不带技术词）
2. **怎么做的**（数据流 + 关键取舍）
3. **怎么验证的**（命令/指标/对比）
4. **边界在哪**（没做什么、为什么）

## 五、明确不做

SpringCloud 全家桶、Nacos/Gateway 实操、K8s、RabbitMQ 部署、分库分表、JVM 调优实战（只讲原理 + 一次 `jstat` 观察）、源码级 Spring 分析。

理由：**面试官问的是"你做过什么、怎么验证、边界在哪"，不是"你背了多少组件"。** 装组件不产生数据，只有交付物能。

## 六、判断达标的标准

- 每个模块能给出一个**可打开的文件**（代码或报告）
- 每个模块能给出一个**数字**（EXPLAIN rows、QPS、命中率、重试次数）
- 每个模块能说出**一个没做和为什么**
- 12 道 JD 题，每题 60 秒内讲完且不出现"大概/应该/可能"
