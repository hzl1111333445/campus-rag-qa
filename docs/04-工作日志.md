## 2026-11-22 下午 · 混合检索 + 相邻块去重 + 可视化网页

> 这一段的主题是**"从能用到好用"**：检索从单路变三路，解决"重复块挤占引用位"，最后把系统做成能看见的网页。

### 一、加 BM25：解决"列举型问题向量漏块"

**遇到的问题**：问「违纪处分有哪几种」，纯向量 Top3 是 #15、#2、#23，而真正含答案清单的 `#3`（"…给予下列之一的处分：（1）警告；…（5）开除学籍"）连 Top10 都没进。

**原因**：向量比"整体意思像不像"。"有哪几种"这个意图在向量空间里被稀释，#2 是总则、满篇"违纪处分"，反而最像。

**解决**：加一路 BM25（按字面命中打分）。

- `service/Tokenizer.java`：中文分词用「单字 + 相邻双字」，`"学生证"` → 学、学生、生、生证、证。不用 jieba/IK 的理由：多几十 MB 词典依赖；bigram 在短文本上效果已接近；换分词器只改这一个类
- `service/Bm25Index.java`：`K1=1.5`、`B=0.75`（业界默认值，**没为本语料调过**）；三点直觉——IDF（越稀有越值钱）、TF 饱和（出现 5 次不等于重要 5 倍）、长度归一化（长块按长度折价）
- `service/RetrievalService.java`：`SearchMode` 三值 + RRF 融合 `w/(60+名次)`，k=60 来自 RRF 原论文；索引按 **`块数:最大块id` 指纹缓存**，上传/删除文档自动重建
- `controller/SearchController.java`：`/api/search?mode=`、`/api/search/compare`（三路对比）、`/api/search/stats`
- 单测 `Bm25IndexTest`：5 个用例（分词、清洗、字面命中排前、全库没有的词得 0 分、IDF 覆盖率）

**证据（8 个问题 × 3 种方式，Top1 文档全对）**：

| 问题 | 向量 Top1 | BM25 Top1 | 混合 Top1 |
|---|---|---|---|
| 转专业需要满足什么条件 | #5 / 0.7217 | #23 / 25.99 | #23 |
| 学生证丢了怎么补办 | #2 / 0.7635 | #2 / 22.19 | #2 |
| **学业证书有哪些** | **#2** / 0.7317 | **#1** / 26.05 | #1 |
| 留校察看多少个月 | #4 / 0.6698 | #4 / 43.22 | #4 |

**真修好的**：「学业证书有哪些」——向量给 #2（讲证书性质），BM25 给 **#1（逐条列出证书种类）**，这正是列举型问题该命中的块。

**没修好的**：「违纪处分有哪几种」三路都没把含清单的块捞进 Top3。说明混合不是银弹：问题里的"哪几种"在原文不出现 → 字面也没抓手；切分又把清单和上下文切开了。

### 二、相邻块去重：解决"Top3 里两块说同一件事"

**遇到的问题**：`overlap=50` 让第 N 块尾部 ≈ 第 N+1 块开头。同一句话同时出现在两块里 → 两块分数接近 → Top3 里两个名额是重复内容。实测「学业证书有哪些」混合结果是 `证书#1、证书#2、辅修#1`，#1 和 #2 内容大量重复。

**解决**：`buildHits()` 排序后，遇到"**同文档 + chunkIndex 相差 ≤ 1**"的块就跳过，直到凑够 topK。

**为什么只判相邻，不判"同文档就去重"**：同一份规定的第 1 块和第 20 块讲的是不同内容（"申请条件" vs "办理流程"），都要留。

**证据**：
```
日志：跳过相邻重复块：05-…学业证书管理规定 #2（分数 24.4344）
      相邻块去重：跳过 1 块，返回 3 块
结果：改前 证书#1、证书#2、辅修#1 → 改后 证书#1、辅修#1、证书#3
```

**诚实记录代价**：被跳过的 #2 分数 24.43，补上来的辅修 #1 只有 18.01 —— 这是**用相关性换多样性**。更好的做法是"把 #1+#2 合并成一块"而不是丢弃（待办）。

### 三、可视化网页：让系统"能看见"

**做法**：`demo/src/main/resources/static/index.html`（单文件，零前端依赖，Spring Boot 自动当静态资源托管），浏览器打开 `http://localhost:8081/` 就是完整界面。

**两个页签**：
1. **智能问答**：输入问题 → 答案 + 引用卡片（点 `[1]` 上标能跳到对应原文卡片并高亮）
2. **检索对比**：一个问题同时看 vector / bm25 / hybrid 三列结果

**三个实现细节**：
- 模型输出**先整体 HTML 转义，再**把 `[n]` 正则替换成可点击上标 —— 顺序反了就是 XSS 漏洞
- 引用卡片显示：文档名 + 第几块 + 相似度 + chunkId + 原文（点一下展开全文）；为此给 `QaService.Reference` 加了 `content` 字段
- 顶部显示索引块数、默认检索方式、向量权重；答案区显示模型名、耗时、检索块数、引用校验徽章

**证据（真实调用）**：
```
POST /api/qa {"question":"学业证书有哪些？","topK":3}
→ model=deepseek-chat  elapsedMs=1232  citations=2  citationOk=true
→ 回答：我校普通高等教育本科的学业证书包括学历证书、学位证书及其他学业证书 [1]。
        辅修专业证书与学历证书配合使用，一般不单独作为学历证书使用 [2]。
→ 引用：[1] 学业证书管理规定 第 2 块 0.0163（原文 205 字）
        [2] 辅修专业修读管理办法 第 2 块 0.0156（原文 219 字）
```

### 四、这一段遇到的问题与解决办法（汇总）

| 问题 | 现象 | 解决办法 | 教训 |
|---|---|---|---|
| 列举型问题向量漏块 | 含清单的块不在 Top10 | 加 BM25 第二路 + RRF 融合 | 单路检索永远有盲区 |
| 两种分数不能直接相加 | 余弦 0~1 vs BM25 0~30 | 用**名次**融合（RRF） | 不同量纲先归一或换指标 |
| 重复块挤占引用位 | Top3 里两块内容重复 | 相邻块（≤1）去重 | overlap 是有代价的 |
| 去重后第 2 名变差 | 24.43 → 18.01 | 暂接受，记录为"待改为合并" | 优化常常是 trade-off |
| BM25 索引重复构建 | 每次查询多花几十毫秒 | `块数:最大块id` 指纹缓存 | 缓存要能被数据变化"驱动失效" |
| 去重后循环越界风险 | 原来 `r < min(topK, n)` | 改成"凑够就 break" | 过滤场景不能按固定次数循环 |
| 页面中文乱码（PS 5.1 抓取） | `Invoke-WebRequest` 得到乱码 | 用 `.NET WebClient` 指定 UTF-8 读取 | 乱码多在解码侧，不在数据侧 |
| 模型输出直接进 innerHTML | 可能 XSS | 先转义，再做引用替换 | 生成内容一律不可信 |

## 2026-11-22 · 补语料 + 补齐问答生成层

### 一、写完了 RAG 的最后一层：问答生成（G）

**新增 6 个文件**

| 文件 | 干什么 | 解决什么问题 |
|---|---|---|
| `config/LlmProperties.java` | 存 DeepSeek 配置（地址、模型、key、温度） | 配置与代码分离，换模型不用改代码 |
| `config/LlmConfig.java` | 把配置注册成 Spring Bean | 让容器知道有这坨配置 |
| `service/ChatClient.java` | 真正向 DeepSeek 发 HTTP 请求 | 系统第一次"会说话" |
| `service/PromptBuilder.java` | 把 3 段资料 + 问题拼成提示词 | 让模型只看我们的资料，不靠它瞎猜 |
| `service/QaService.java` | 串流程：检索 → 拼词 → 调模型 → 引用校验 → 组装 | 一条命令走完 RAG 最后一公里 |
| `controller/QaController.java` | `POST /api/qa`、`GET /api/qa/preview` | 前端/curl 可调用 |

**这一层解决的问题**：检索层只给 3 段原文，生成层把 3 段原文变成「一句人话 + 标好出处」。

具体解决三件事：

1. **用户不想看原文，要答案**
   - 之前输出：`[{score:0.67, content:"…一等奖学金 2000 元/人…"}]`
   - 现在输出：`一等奖学金为 2000 元/人 [2]。资料中仅此一处明确列出该金额。`

2. **答案必须能追溯出处**
   - 提示词硬规则：每条结论标 `[n]`，编号必须真实存在
   - `QaService` 用正则 `\[(\d{1,2})]` 抠出编号，校验是否超出资料条数

3. **资料里没有时必须说"没有"，不许编**
   - 提示词规则：资料不足就回「资料中没有找到相关规定，建议咨询学校相关职能部门」

**实测证据（DeepSeek 真调用）**

| 测试题 | 耗时 | 模型表现 |
|---|---|---|
| 奖学金一等多少钱 | 786ms | 答对 2000 元，引用 `[2]` 合法 ✅ |
| 旷课多少学时被处分 | 1085ms | 主动说"资料中没有具体学时标准"，并区分 `[1]` 是扣分不是处分 ✅ |
| 违纪处分有哪几种 | 1563ms | 内容对，但**引用标错块**（标 `[2]`，实际不在这块）⚠️ |

**能力边界（必须记住）**：提示词挡得住"它不确定的时候"，挡不住"它确信但资料里没写的时候"。第三条就是这种情况——内容真实（全国高校都这五种），但出处是假的。要解决得靠 groundedness 校验。

## 2026-11-19 · 流水线跑通（上传 → 解析 → 切分 → 向量化 → 检索）

### 一、上传与入库

- `POST /api/document/upload`（multipart）：存磁盘（UUID 命名，防重名覆盖 + 防 `../` 路径穿越）→ 写 `kb_document`（status 0）→ 解析 → 切分 → 写 `kb_chunk` → status 2
- 数据库 `campus_rag`：`kb_document`、`kb_chunk`（含 `embedding MEDIUMTEXT`、`embedding_model`、`embedding_dim`）

### 二、解析（Tika 3.3.3）

- `DocumentParser`：txt/md 走 UTF-8 自解码（Tika 常把中文短文猜成 GBK）；PDF/docx 走 Tika `AutoDetectParser` + `BodyContentHandler(-1)`（-1 不限长度，默认只留 10 万字）
- 扫描件识别阈值：最终定 50 字（依据：能读的最少 2036 字，读不出全是 0 字）

### 三、切分（TextSplitter）

- 滑动窗口 + 句末回退 + 重叠；`SENTENCE_END = "。！？；\n"`
- 三个真问题及修法：
  1. **换行被当句子边界**（PDF 每行 15~30 字）→ 删除文本里的换行
  2. **回退 + 重叠双重缩短**（220 窗口退到 150，下一块起点只前移 100）→ `minChunk = size * 0.65` 设回退下限
  3. **1 字碎片**（回退后 end 离 start 太近）→ 小于 10 字并入前一块
- 效果：块数 748 → **305**，平均块长 99 → **195** 字，最短块 1 → **132** 字

### 四、向量化（硅基流动 bge-m3，1024 维）

- `OpenAiEmbeddingClient`：POST `/embeddings`，按 `data[].index` 排序后取（返回顺序不保证），统一 L2 归一化，维度不符直接抛错
- `EmbeddingService.embedPending`：每 16 条一批，`WHERE embedding IS NULL` 增量补齐
- 实测：295 条 / 19 批 / **6.1 秒**
- 清理重复文档后：305 块 → 189 块 / 6 份

### 五、检索（纯向量）

- `RetrievalService.search(question, topK)`：问题向量化 → 取全库向量 → 点积 → 排序 → Top3
- `GET /api/search?q=&topK=`
- 实测：「违纪处分有哪几种」Top1 0.6358（正确文件）；「奖学金一等多少钱」0.6719（但金额被切到上一块）；「食堂几点开门」三条全错 0.50~0.51 → 说明**必须设相似度阈值**
