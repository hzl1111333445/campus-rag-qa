## 2026-11-22 · 补语料 + 补齐问答生成层

### 一、写完了 RAG 的最后一层：问答生成（G）

**新增 6 个文件**

| 文件 | 干什么 | 解决什么问题 |
|---|---|---|
| `config/LlmProperties.java` | 存 DeepSeek 配置（地址、模型、key、温度） | 配置与代码分离，换模型不用改代码 |
| `config/LlmConfig.java` | 把配置注册成 Spring Bean | 让容器知道有这坨配置 |
| `service/ChatClient.java` | 真正向 DeepSeek 发 HTTP 请求 | 系统第一次"会说话" |
| `service/PromptBuilder.java` | 把 3 段资料 + 问题拼成提示词 | 让模型只看我们的资料，不靠它瞎猜 |
| `service/QaService.java` | 串流程：检索 → 拼词 → 调模型 → 引用校验 → 组装 | 一条命令走完 RAG 最后一公里 |
| `controller/QaController.java` | `POST /api/qa`、`GET /api/qa/preview` | 前端/curl 可调用 |

**这一层解决的问题**：检索层只给 3 段原文，生成层把 3 段原文变成「一句人话 + 标好出处」。

具体解决三件事：

1. **用户不想看原文，要答案**
   - 之前输出：`[{score:0.67, content:"…一等奖学金 2000 元/人…"}]`
   - 现在输出：`一等奖学金为 2000 元/人 [2]。资料中仅此一处明确列出该金额。`

2. **答案必须能追溯出处**
   - 提示词硬规则：每条结论标 `[n]`，编号必须真实存在
   - `QaService` 用正则 `\[(\d{1,2})]` 抠出编号，校验是否超出资料条数

3. **资料里没有时必须说"没有"，不许编**
   - 提示词规则：资料不足就回「资料中没有找到相关规定，建议咨询学校相关职能部门」

**实测证据（DeepSeek 真调用）**

| 测试题 | 耗时 | 模型表现 |
|---|---|---|
| 奖学金一等多少钱 | 786ms | 答对 2000 元，引用 `[2]` 合法 ✅ |
| 旷课多少学时被处分 | 1085ms | 主动说"资料中没有具体学时标准"，并区分 `[1]` 是扣分不是处分 ✅ |
| 违纪处分有哪几种 | 1563ms | 内容对，但**引用标错块**（标 `[2]`，实际不在这块）⚠️ |

**能力边界（必须记住）**：提示词挡得住"它不确定的时候"，挡不住"它确信但资料里没写的时候"。第三条就是这种情况——内容真实（全国高校都这五种），但出处是假的。要解决得靠 groundedness 校验。

### 二、补语料：12 份扫描件 OCR 入库

**问题**：14 份校内文件是扫描件（只有图片没有文本层），Tika 提取出来是 0 字，入库全失败，而**学籍类 10 份全在里面**——学生最常问的恰好是学籍。

**做法**：写离线 OCR 脚本 `ocr_batch.py`（Python + PyMuPDF 渲染 + Windows 自带 OCR 引擎），把扫描件转成 txt，再走已有的上传接口入库。

| 指标 | 数值 |
|---|---|
| 处理文件 | 12 份（去重后） |
| 页数 | 107 页 |
| 识别字符 | 40,127 字（汉字 34,478） |
| 耗时 | 32.9 秒（单页 0.22 秒） |
| 新增依赖 | 无（PyMuPDF 已有 + Windows 自带 OCR） |

**质量抽查**（学籍管理规定 16 页）：句子完整、标点正确，「第一条」到「第五十四条」共 56 个条号全部识别，到附则结束无截断。

**已知噪声**（不影响检索）：每页混进页码、引号方向错（`“ 学校 "`）、个别括号丢半个（`三）（四）情形者`）。

## 2026-11-19 · 流水线跑通（上传 → 解析 → 切分 → 向量化 → 检索）

### 一、上传与入库

- `POST /api/document/upload`（multipart）：存磁盘（UUID 命名，防重名覆盖 + 防 `../` 路径穿越）→ 写 `kb_document`（status 0）→ 解析 → 切分 → 写 `kb_chunk` → status 2
- 数据库 `campus_rag`：`kb_document`、`kb_chunk`（含 `embedding MEDIUMTEXT`、`embedding_model`、`embedding_dim`）

### 二、解析（Tika 3.3.3）

- `DocumentParser`：txt/md 走 UTF-8 自解码（Tika 常把中文短文猜成 GBK）；PDF/docx 走 Tika `AutoDetectParser` + `BodyContentHandler(-1)`（-1 不限长度，默认只留 10 万字）
- 扫描件识别阈值：最终定 50 字（依据：能读的最少 2036 字，读不出全是 0 字）

### 三、切分（TextSplitter）

- 滑动窗口 + 句末回退 + 重叠；`SENTENCE_END = "。！？；\n"`
- 三个真问题及修法：
  1. **换行被当句子边界**（PDF 每行 15~30 字）→ 删除文本里的换行
  2. **回退 + 重叠双重缩短**（220 窗口退到 150，下一块起点只前移 100）→ `minChunk = size * 0.65` 设回退下限
  3. **1 字碎片**（回退后 end 离 start 太近）→ 小于 10 字并入前一块
- 效果：块数 748 → **305**，平均块长 99 → **195** 字，最短块 1 → **132** 字

### 四、向量化（硅基流动 bge-m3，1024 维）

- `OpenAiEmbeddingClient`：POST `/embeddings`，按 `data[].index` 排序后取（返回顺序不保证），统一 L2 归一化，维度不符直接抛错
- `EmbeddingService.embedPending`：每 16 条一批，`WHERE embedding IS NULL` 增量补齐
- 实测：295 条 / 19 批 / **6.1 秒**
- 清理重复文档后：305 块 → 189 块 / 6 份

### 五、检索（纯向量）

- `RetrievalService.search(question, topK)`：问题向量化 → 取全库向量 → 点积 → 排序 → Top3
- `GET /api/search?q=&topK=`
- 实测：「违纪处分有哪几种」Top1 0.6358（正确文件）；「奖学金一等多少钱」0.6719（但金额被切到上一块）；「食堂几点开门」三条全错 0.50~0.51 → 说明**必须设相似度阈值**
