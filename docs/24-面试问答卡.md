## 卡 1 ✅ 为什么拒答放在检索层，而不是让模型说"我不知道"？

**一句话（背这句）**：
> **让模型判断"自己不知道"，它做不到；让检索分数判断，可以量化。所以拒答放在检索层，0.44 秒返回，不花钱。**

**证据**
- 模型有"帮忙本能"（RLHF 训出来的），资料不相关时它会硬凑一个像样的答案——我们 48.3% 的幻觉就是这么来的
- 时间：检索层拒答 **0.44 秒**；让模型说一遍要 **1.4~2.5 秒**，还花 token
- 阈值可复现：扫 0.005~0.1，取 **0.015** 时误拒 2 道 / 正确拒 1 道（见 `docs/09-拒答阈值`）

**边界（主动说）**
检索层只能拦"资料根本对不上"；资料相关但需要推理/跨条汇总的，它拦不住。所以还有第二层（提示词里写死拒答话术）、第三层（接地校验标出没依据的数字）。

**代码**：`QaService.prepare()` 两道早退（`hits.isEmpty()` / `best.gated()`）

**别这么说**：别说"模型不知道自己不知道"就完了——要补"所以我用可量化的分数替它判断"。

## 卡 2 ✅ `citationOk` 为什么不能写成 `invalid.isEmpty() && !cited.isEmpty()`？

**一句话**：
> **布尔只能装两态，产品有三态。拒答本来就不该带编号，"没引用"不是"引用出错"。**

**证据**
- 拒答时答案里没有 `[1]` → `cited` 为空 → 原写法判 false → 前端弹红标签，像出了事故
- 正确语义：`citationOk` = "**没有编造资料里不存在的编号**"；"有没有引用资料"看 `references.size()`
- 产品三态：🟢 引用通过 / 🔴 编号越界 / ⚪️ 未引用资料 → 前端 `citeTag()`

**边界**：这个改动只影响"显示是否准确"，不影响答案内容；真正的引用错误要靠越界检测 + 接地校验两道。

**代码**：`QaService.validate()` 第 290 行，附近 287–289 行还留着注释解释（面试可以直接指给面试官看）

## 卡 4 ✅ 引用校验 vs 接地校验，区别是什么？

**一句话**：
> **引用校验查"编号标得对不对"，接地校验查"标了的地方真有这句话吗"。前者防瞎标，后者防瞎写。**

**证据**
- 只有一层不够的证据：问"违纪处分有哪几种"，模型把五种处分答对了却标成 `[2]`，而清单其实在第 3 块——**编号合法、出处错误**
- 接地校验只核**硬事实**：数字+单位（学时/元/天/个月/年/瓦/册/工作日/%）、时间点（`23:30`）、处分名（警告/严重警告/记过/留校察看/开除学籍）
- 实测：120 题里接地通过 **119/120**

**边界**：只认字面，抓不到"语义改写"（"需辅导员签字"换成"须辅导员批准"它就发现不了）；做语义核对要上 embedding 或二次 LLM，成本和延迟都得涨。

**代码**：`QaService.validate()` + `AnswerGuard.check()`

## 卡 5 ✅ 接地校验具体怎么做的？

**一句话**：
> **抽硬事实 → 归一化 → 在被引块原文里做包含判断；找不到不是"一定错"，但一定标出来。**

**证据（三步）**
1. **抽**：两条正则 + 一张词表（数字+单位 / 时间点 / 五个处分名）
2. **归一化**：全角转半角、去空白、去小数尾零（否则"1.5 元"和"1.50 元"会被判成不匹配）
3. **找**：把**所有被引块拼成一个大字符串**再逐条 `contains`（这样跨块被引用的数字也能命中）

**两个细节**
- 没有事实 / 没有引用块 → 返回 `grounded=false` 且 `missingCount=0`（"没东西可核" ≠ "核过通过"）
- 只核硬事实不核措辞，才不会大量误报

**边界**：零模型调用、便宜、可解释；代价就是只认字面。

**代码**：`demo/src/main/java/com/campus/rag/service/AnswerGuard.java`（189 行）`extract()` / `normalizeDigits()` / `check()`

## 卡 6 ✅ 多轮上下文怎么带？历史会不会污染？

**一句话**：
> **历史只用来理解"用户在指什么"，不作事实来源；所以只带 3 轮、一条 120 字、超了整条丢、编号全抹掉。**

**证据**
- 只带 **3 轮**：够认出"那、还、这个"，再多只会让模型把上一轮的话当资料，token 也翻倍
- 单条 **120 字**截断：历史用来认指代，不是复述内容
- 总量超 **600 字**就**整条丢**（不截半条——半句话比没有更糟）
- **抹掉历史里的 `[n]`**：模型会照抄上一轮编号，导致"编号合法、出处全错"，这比不写编号更危险
- 提示词里写死："历史里助手说过的话不算资料，不得作为依据，也不得出现在引用编号里"

**边界**：8 组追问对照 Top1 从 **3/8 → 8/8**，但样本小；120 题单轮回归零变化，说明不拖累单轮。

**代码**：`ContextAssembler.assemble()` + `PromptBuilder` 历史段

## 卡 9 🔶 为什么两路召回？只用向量不行吗？

**一句话**：
> **向量看"意思"，BM25 看"字面"，两种错法不一样，所以能互补；但没法直接加权相加，因为量纲不同。**

**证据（118 道应答题的实测）**

| 配置 | Recall@3 | MRR |
|---|---|---|
| 纯向量 | 76.27% | 0.6299 |
| 纯 BM25 | 77.12% | 0.6822 |
| 混合 RRF | 80.51% | 0.7274 |
| 混合 + 精排 | 88.14% | 0.8192 |
| **线上（双查询融合+精排+展开邻居）** | **90.68%** | **0.8531** |

- 不能直接相加：余弦相似度 0~1，BM25 能到 30+ 且无上界 → 用 **RRF 按名次融合** `Σ 1/(60 + rank)`
- 中文没有空格 → BM25 用 **bigram（单字 + 双字）**，`K1=1.5`、`B=0.75`

**边界（主动说）**：**硬改写题只有 76.67%**——用户换一套说法（"被记过还能入党吗"），两路都弱；靠查询改写能提到 73.33%（改写+精排+展开配置），但这是当前最大短板之一。

**代码**：`RetrievalService.searchBestGated()` + `Bm25Index`

## 卡 11 ✅ 手写 BM25 怎么算分？为什么用 bigram？

**一句话**：
> **BM25 = IDF 加权 + 词频饱和 + 长度归一化；中文没有空格，所以用 bigram（单字 + 双字）当"词"。**

**证据（公式，两行）**
```
idf = ln(1 + (N - df + 0.5) / (df + 0.5))
score = Σ idf * (tf * (K1+1)) / (tf + K1 * (1 - B + B * len/avgLen))
```
- **IDF**：越少见的词权重越大（`df == N` 时仍为正，因为有 `+1`）
- **K1 = 1.5**：词频饱和——同一个词出现 3 次不等于 3 倍分，防止关键词堆砌刷分
- **B = 0.75**：长度归一化——长块天然命中更多词，不归一化它会占便宜
- **bigram**：`宿舍楼` → `宿舍`/`舍楼` + 单字，解决中文无空格
- 建索引一次 O(总词数)（643 块约 3 万 token，几毫秒），用 `fingerprint = 块数 + 最大块 id` 做缓存，上传/删除文档才重建

**两个细节（显得真读过代码）**
1. `df` 统计时**同一块里出现多次只算一次**（第 90 行），否则高频词 df 虚高、IDF 被压
2. 查询词在全库 `df == 0` 时**直接跳过，不能给惩罚分**（135–138 行注释）——惩罚会让所有块一起掉分，改变不了排序，纯浪费

**边界（主动说）**
- BM25 只认**字面**：118 道应答题 Recall@3 **77.12%**，硬改写题只有 **66%**
- 分数**没有上界**（能到 30+），和余弦相似度（0~1）**不能直接相加** → 所以用 RRF 按名次融合
- 中文 bigram 会产生少量跨词噪声（"上晚"这种），但对规章文本影响可接受

**代码**：`demo/src/main/java/com/campus/rag/service/Bm25Index.java`（218 行）`build()` / `scores()`

## 卡 12 ✅ RRF 为什么用名次不用分数？k=60 哪来的？

**一句话**：
> **两种分数的量纲没法比（余弦 0~1，BM25 0~30+），直接相加等于让 BM25 说了算；RRF 只比名次，不需要标度。**

**证据（就是这一行）**
```java
fused[块] = wVector / (60 + 向量名次 + 1) + wBm25 / (60 + BM25名次 + 1);
```
- 默认 `wVector = 0.2`、`wBm25 = 0.8`（在"题面和原文共用汉字"的题上调出来的）
- **k = 60** 来自 2009 年那篇 RRF 论文，作用是**把名次差距压平**：
  第 1 名 `1/61 ≈ 0.01639`，第 2 名 `1/62 ≈ 0.01613`，只差 **1.6%** → 不会因为某一路的第一名完全决定结果
- 效果（118 道应答题）：纯向量 76.27% / 纯 BM25 77.12% → **混合 RRF 80.51%**（+3.4pt），MRR 0.7274

**为什么不用"分数加权求和"（面试会追）**
- 余弦 0~1，BM25 能到 30+，**直接相加 BM25 一家说了算**
- 归一化（min-max / z-score）能凑，但 min-max 对异常值敏感、z-score 要假设分布，效果不稳
- RRF 只用名次 = **无标度（scale-free）**，换数据集不用重调

**两个真踩过的坑（说出来很加分）**
1. **权重借错**：双查询融合时误用了 `0.2`（那是"向量权重"），结果与纯混合**完全相同** = 白测一次
2. **自适应权重失败**：按 BM25 信号强弱动态调权重，实测只多对 1~2 道、dev 零变化 → 默认关闭

**边界（主动说）**
- RRF **丢了分数强度**：它不知道第一名是 0.99 还是 0.31 → 所以后面还要接**精排**（Cross-Encoder 直接看"问题-块"对，给绝对分）
- RRF 分只有 **0.016 量级**，和精排分（0~1）**不同量纲** → 所以配置里是**两个阈值**（`min-score-rerank` / `min-score-hybrid`），用一个数卡两种分必然有一边错

**代码**：`demo/src/main/java/com/campus/rag/service/RetrievalService.java:821` `rrf()`、`:841` `ranksOf()`、常量 `RRF_K=60`（第 45 行）

## 卡 13 ✅ 精排服务挂了怎么办？

**一句话**：
> **精排是"第二阶段打分"，我把它当成会挂的外部依赖：调不通就退回粗排结果、接口不中断——代价是分数口径变了，所以阈值必须两套。**

**证据（就是这三行）**
```java
if (!rerankClient.available()) { ... }          // 没启用 → 直接用混合结果截前 K
double[] scores = rerankClient.scores(...);      // 调用精排
if (scores == null) { ... }                      // 调用失败 → 保持粗排顺序，只截前 K
```
- `RerankClient.scores()` 有**三条**返回 `null` 的路径：未启用/文档为空（71–72）、响应结构不符（93）、运行时异常被 `catch`（105–107）
- 候选池比最终结果多：`candidates = max(topK, rerankProperties.candidates)`（默认 10 → 取 3），粗排多留余地给精排挑
- 成功路径才重排：`orderByScoreDesc(scores)` → 按新名次取前 K，分数保留 4 位小数

**为什么必须降级而不是抛错**
- 精排是**外部 HTTP 服务**（bge-reranker-v2-m3），网络抖、限流、模型下线都会让它返回不了
- 搜索是用户主路径：宁可给"稍差但可用"的 3 块，也不能给 500
- 降级后行为可预期：顺序仍是 RRF 的合理顺序，只是少了精排那 5~7pt

**边界（主动说，这是加分点）**
- **降级后分数不是同一种分**：精排分 0~1（真能答 0.5~0.9），RRF 分只有 0.016 量级 → 所以配置里是**两个阈值**（`min-score-rerank` / `min-score-hybrid`），共用一个数必然有一边错
- 收益是实测的，不是猜的：混合 80.51% → 混合+精排 88.14%（+7.6pt），所以精排值得依赖，但不能是硬依赖
- 还没做的：**熔断/重试**。现在每次请求都会试一次精排，失败就降级；生产上应该加"连续 N 次失败后冷却 60 秒"，省掉重复超时

**代码**：`demo/src/main/java/com/campus/rag/service/RerankClient.java:70` `scores()`、`:105` `catch`、`demo/src/main/java/com/campus/rag/service/RetrievalService.java:340` `rerankedHits()`、`:346` `available()`、`:356` `scores == null`

**别这么说**：别说"精排保证准确率更高"（它是外部服务、会抖会挂）；也别说"降级就等于没事"（阈值与分数口径会错位）。
