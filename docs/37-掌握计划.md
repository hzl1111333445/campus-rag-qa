# 掌握计划：把简历上的每一条变成"我能讲、我能改"

> 问题不是"没学过"，是**参与度低**：代码是我写的，你只看见结果。
> 所以这份计划的核心不是"再讲一遍课"，而是**每个模块你都要亲手改一次、并且讲给录音听**。
> 目标不是"全部掌握"，是**面试官问到的地方，你答得出结论 + 证据 + 边界**。

## 一、诊断：你现在的三层缺口

| 层 | 表现 | 能不能速成 |
|---|---|---|
| L1 不知道代码在哪 | 问"切分在哪"要翻半天 | ✅ 30 分钟能解决（给你文件:行号地图） |
| L2 不知道为什么这么写 | 能说"用了 RRF"，说不出"为什么不用加权求和" | 🟡 要靠讲 + 追问逼出来 |
| L3 不知道改坏了会怎样 | 没跑过对照，答不出"去掉精排掉几个点" | 🔴 **必须动手，没有捷径** |

**面试真正区分人的是 L2 和 L3。** L1 靠地图，L2 靠背+讲，L3 只能靠做实验。

## 七、话术模板（每个答案都套这个）

```
结论：一句话给判断（不带"可能""大概"）
证据：一个数字 或 一个文件:行号 或 一次对照实验
边界：什么情况下这个结论不成立 / 我没做的是什么
```

**示例（RRF 为什么不用加权求和）**：

> **结论**：因为向量分和 BM25 分不在一个量纲上，加权求和要先归一化，而归一化会让"两路都还行"的文档被抬得过高。
> **证据**：我做过对照——加权求和那版把 BM25 权重借给向量（0.2），结果和纯混合完全一样，等于白调一轮；换成 RRF 只用排名不用分数，混合比单路高 3~5 个点。
> **边界**：RRF 也有代价，它丢掉了分数信息，所以"某一路特别自信"这种情况它体现不出来；这也是我后面加精排的原因。

## 八、三条纪律（防止又变成"看视频"）

1. **不写代码不算学会**：每个模块必须有一次自己的 diff，`git log` 里能看到。
2. **不录音不算会讲**：讲给手机听，回放时只记卡点，不自我评价。
3. **答不出就进清单**：每次模拟面试后写"未掌握清单"，第二天只补清单里的。
