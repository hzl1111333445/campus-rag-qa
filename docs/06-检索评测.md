# 06 · 检索评测：混合检索到底比纯向量好多少

> 前面五步（解析、切分、向量化、检索、生成）回答的是「能不能跑通」。
> 这一章回答的是「**到底好不好**」——用数字说话，而不是「感觉还行」。

---

## 1. 为什么要专门做一批评测

面试官和答辩老师不会问「你有没有做 RAG」，会问：

- 你的检索准确率多少？怎么测的？
- 混合检索比纯向量好多少？凭什么说好？
- 哪些问题答不好？为什么？

没有这张表，简历上只能写「实现了 RAG 问答系统」；有了这张表，能写
「**在自建 32 道校园规章题目上，混合检索把 MRR 从 0.76 提升到 0.82，并定位出三类系统性漏检**」。

---

## 2. 评测怎么做的

### 2.1 题集

文件：`data/testset/eval_questions.tsv`（36 题，随代码进 Git）

| 项 | 值 |
|---|---|
| 总题数 | 36 |
| 参与检索评测 | **32**（跳过 4 道「无答案」题，它们属生成层评估） |
| 题型分布 | 数值型 15 / 流程型 7 / 事实型 6 / 列举型 4 / 无答案 4 |
| 覆盖文档 | 17 份（全部入库文档） |
| 关键词校验 | `tools/verify_testset.py` 逐题确认「同时包含全部关键词的块数 ≥ 1」 |

每题格式：`id → 问题 → 标准答案关键词（| 分隔） → 题型 → 难度`

### 2.2 判定口径

**命中（hit）**：返回的前 K 条里，有任意一条的内容同时包含该题**全部**关键词。

为什么用关键词而不是人工打分：

- 可复现、可批量、不掺主观
- 缺点：偏宽（块里出现这些词不代表真回答了问题），所以后面还要配生成层评测

**Recall@3** = 命中题数 / 参与题数（正确答案有没有进前 3）
**MRR** = 每题 `1 / 首次命中名次` 的平均（排第 1 得 1.0，第 2 得 0.5，第 3 得 0.33，没进前 3 得 0）

### 2.3 参评的四种配置

| code | 名称 | 说明 |
|---|---|---|
| `vector` | 纯向量 | bge-m3（1024 维）余弦相似度排序 |
| `bm25` | 纯 BM25 | 单字 + 双字分词，K1=1.5 / B=0.75 |
| `hybrid` | 混合 RRF | 向量权重 0.2、BM25 权重 0.8，RRF k=60，**带相邻块去重** |
| `hybrid_no_dedupe` | 混合 RRF（不去重） | 同 hybrid，但关掉去重，用来验证去重的价值 |
| `hybrid_rerank` | 混合 + 精排 | 粗排取 10 条候选 → Cross-Encoder 重排 → 取前 3（D 轮新增，详见 [07-精排](07-精排（Rerank）.md)） |

同一批问题、同一个索引（414 块）、同一次运行（`GET /api/eval/run?topK=3`，6489ms）。

## 4. 按题型拆解（这才是关键）

| 配置 | 事实型 | 数值型 | 流程型 | 列举型 |
|---|---|---|---|---|
| 纯向量 | **5/6 = 0.83** | 12/15 = 0.80 | 7/7 = 1.00 | **4/4 = 1.00** |
| 纯 BM25 | **6/6 = 1.00** | 13/15 = 0.87 | 7/7 = 1.00 | **4/4 = 1.00** |
| 混合 RRF | 6/6 = 1.00 | 13/15 = 0.87 | 7/7 = 1.00 | 4/4 = 1.00 |
| 混合（不去重） | 6/6 = 1.00 | 13/15 = 0.87 | 7/7 = 1.00 | 4/4 = 1.00 |
| **混合 + 精排** | 6/6 = 1.00 | **14/15 = 0.93** | 7/7 = 1.00 | 4/4 = 1.00 |

三个反差现象（下面的数字均为本次重跑，与第 3 节一致）：

### 4.1 向量最弱的是「数值型」（0.80，MRR 仅 0.6556）

向量漏了 3 个数值型题（#12 国家奖学金多少钱、#15 一等奖学金多少钱、#17 旷课多少学时），
另外还漏了 #18「上课迟到怎么算」。

共同点：问题问的是**具体数字或具体换算**，而块里写的是另一套表述——
「要交钱」原文是「工本费」，「迟到怎么算」原文是「迟到 15 分钟以上按旷课 1 节计」。

按理说向量模型最擅长这种语义匹配，为什么反而漏？

因为本项目的 bge-m3 是**通用中文模型**，对「工本费 / 交钱」这类校园事务性表述并不敏感；
相反 BM25 只要命中「学生证」「补办」这种字面就够。

**这条要记住**：向量 ≠ 一定懂语义，通用 embedding 在垂直领域经常追不上字面检索。
但反过来说，向量在**列举型**上是满分的（4/4，MRR 0.875）——所以两路必须混合。

### 4.2 BM25 现在在「列举型」上不弱了（4/4）

这一点与 C-2 首次运行的结论**相反**（当时 3/4）。原因不是算法变了，而是**语料重新切分后，
「违纪处分有哪几种」的清单块不再被劈成两半**——同一个问题，块边界一改，结论就翻。

**这是本项目最重要的一条方法论**：检索实验里，"改动语料"和"改动算法"对指标的影响是同一量级的，
所以每次重跑都要先确认「块集有没有变」，否则比的不是算法。

### 4.3 流程型的 MRR：向量第一（0.9286），混合在它之后（0.8571），精排最高（1.00）

混合在流程型上 Recall 满分但 MRR 更低，说明**正确答案还在前 3，只是被排到第 2、3 名**。

原因：流程类问题里出现大量「申请」「办理」这类高频词，BM25 给它们的 IDF 很低，
而向量那一路又把这些词看得很重 → RRF 融合后，正确答案被几个「关键词很密但流程不对」的块挤后了一位。

**精排把这块补回来了（MRR 1.00）**——因为 Cross-Encoder 能看出"这块讲的是全过程步骤，还是只提了一句办理"。

用 `GET /api/search?topK=10&mode=hybrid` 把正确块在**前 10 名**里的位置找出来：

| 题 | 正确块 | 在前 10 里的名次 | 为什么 |
|---|---|---|---|
| #12 国家奖学金一年多少钱 | chunkId=1473《国家奖助学金实施办法》第 5 块（含「国家奖学金的奖励标准为每生每年 10000 元」） | **第 4** | 前 3 名是同文档的评审程序、申请资格块，都在说「国家奖学金」但**不含金额**——关键词密度赢了，答案没有 |
| #16 综合测评里学业成绩占多大比重 | chunkId=1279《综合测评条例》第 0 块（含「学业表现分…乘以 70% 后计入总分」） | **第 4**（A 方案前是第 10） | 块头加前缀后从第 10 名升到第 4 名，但前面仍有 3 块把「综合测评」写得更密集 |
| #19 违纪处分有哪几种 | chunkId 见《违纪处分条例》第 3 块（含「（1）警告；（2）严重警告；（3）记过；（4）留校察看；（5）开除学籍」） | **已进前 3** | 重新切分后清单不再被劈成两半，本题已由 BM25 捞回 |

**前两次是一个信息**：正确块进不了前 3，不是因为「找不到」，而是因为**候选里的干扰块字面更匹配**。
第三条则说明：**改数据结构（切分/前缀）比改算法更管用**——但改完要重跑，否则比的是上一次的语料。

## 6. 五条结论

> 以下数字均为「A 方案 + 精排」实施后重跑的结果。

1. **算法换不来召回，数据结构才换得来。** 三种检索方式的 Recall 都是 0.9375（30/32）；
   真正把 0.875 抬到 0.9688 的是**块头前缀（A 方案）**和**精排（D 方案）**，不是换检索算法。
2. **混合检索的真实收益是「排序」而不是「召回」。** MRR：BM25 0.8385 → 混合 0.875（+4.4%），Recall 不动；
   精排再推到 **0.9063（+8.1%）**。简历上应该写 MRR，不是写「召回率提升」。
3. **相邻块去重是正收益，但不大。** 去重前后：Recall 都是 0.9375，MRR 0.8646 → 0.875（+1.2%）。
   代价是可能丢掉补充信息，所以做成可关的开关来量化。
4. **结论高度依赖语料，不能照搬别处经验。** 之前在虚构语料 70 题上测出「BM25 强、向量弱」的相反格局；
   本校真实规章上，向量在**列举型**上是满分的（4/4）。所以论文里所有数字都必须标注「在本文构建的 32 题上」。
5. **「正确答案排第 4 名」是可修的问题，修法是两阶段检索。** 精排把候选从 3 扩到 10 再重排，
   #12、#16 都被顶上前 3 —— 这就是两阶段检索的直接价值（有数据支撑，不是跟风）。

## 10. 实验二：给块加「文档标题 + 章节名」前缀（A 方案）

**动机**：badcase #16 表明，正确块开头是页码 `— 3—`，块里没有"综合测评"字样 → 字面检索打不中、向量也不像。

**做法**：入库时给每个块前面拼 `【文档标题 · 第X章】`（新建 `ChunkEnricher`，在 `DocumentIngestService` 里切分后调用）。
章节名按"继承"处理：某块没出现"第X章"就沿用前文最近的章节。
**必须在入库时加**——向量是入库时算的，检索时再拼就晚了。

**验证**：`POST /api/dev/reingest-all?force=true`（17 份 / 414 块，2724ms）→ `POST /api/dev/embed-all`（414 块重算，8996ms）→ `GET /api/eval/run?topK=3`。

### 10.1 改前 vs 改后

| 配置 | Recall@3 改前 | Recall@3 改后 | MRR 改前 | MRR 改后 |
|---|---|---|---|---|
| 纯向量 | 0.9063 | **0.8750 ↓** | 0.7604 | 0.7604 = |
| 纯 BM25 | 0.9063 | 0.9375 ↑ | 0.8125 | 0.8385 ↑ |
| **混合 RRF** | 0.9063 | **0.9375 ↑** | 0.8229 | **0.8750 ↑** |
| 混合（不去重） | 0.8750 | 0.9375 ↑ | 0.8125 | 0.8646 ↑ |

### 10.2 按题型（混合 RRF）

| 题型 | 改前 Recall | 改后 Recall | 改前 MRR | 改后 MRR |
|---|---|---|---|---|
| 事实型 | 1.00 | 1.00 | 0.9167 | 0.9167 |
| 数值型 | 0.8667 | 0.8667 | 0.8333 | 0.8333 |
| 流程型 | 1.00 | 1.00 | 0.7619 | **0.8571 ↑** |
| 列举型 | 0.75 | **1.00 ↑** | 0.75 | **1.00 ↑** |

**#19「违纪处分有哪几种」被救回来了**：前缀里带了「04-广州软件学院学生违纪处分条例」，含清单的块现在排第 1 且 MRR 1.0。

### 10.3 两个相反的发现（重要）

**发现 1：同一个改动对纯向量是负收益。**
向量 Recall 0.9063 → 0.8750，新增漏检 #15（一等奖学金多少钱）、#17（旷课多少学时）、#18（上课迟到怎么算）。
原因：前缀里的「广州软件学院」「条例」「办法」这类词在所有块里都出现，**稀释了正文的语义向量**；
BM25 反而受益，因为 IDF 会把这些高频词压到很低，真正起作用的还是「综合测评」这类词。
→ 论文可以写：**结构化前缀对字面检索有利、对稠密向量有稀释效应**。

**发现 2：剩下的两个漏检都是「第 4 名」，差一名。**
- #12「国家奖学金一年多少钱」：正确块（含"每生每年 10000 元"）排第 **4**，前 3 名都在讲评审程序
- #16「综合测评里学业成绩占多大比重」：正确块从第 **10** 名升到第 **4** 名，前 3 名讲的是"综合表现占 30%"

这两题已经不是"找不到"，而是"排序差一点"——**这就是下一步做重排（Cross-Encoder）的直接数据依据**。

### 10.4 结论

1. 块头前缀是**低成本正收益**：混合 RRF 的 Recall +0.031、MRR +0.052（相对提升 6.3%）
2. 但要**分检索方式看**：只做纯向量的系统加这个前缀会退步
3. 下一步该做重排，而不是继续调切分——因为剩余误差已经集中在"排序"而不是"召回"

| 合并相邻块 + 精排 | 94.87% | 0.8974 | 97.62% | 91.67% |
| 混合 + 展开邻居 | 93.59% | 0.8953 | 97.62% | 88.89% |
| **精排 + 展开邻居（线上）** | **97.44%** | **0.9167** | 97.62% | **97.22%** |

线上链路明细：dev 41/42 = **97.62%**（MRR 0.9405）、test 35/36 = **97.22%**（MRR 0.8889）。
漏题只有 2 道：`#2 一年可以申请几次转专业`、`#43 学业预警是怎么触发的`。

### 7.4 三条新结论

1. **test 上的差距比 dev 小得多**：dev 里"混合不去重"能到 97.62%，test 只有 88.89%——**只看 dev 会高估方法收益**，这正是要拆验证集的原因。
2. **线上链路在 test 上依然最好**（97.22%），且 dev/test 只差 0.4 个点，说明它不是靠过拟合堆上去的。
3. **精排 + 展开邻居的 MRR 在 test 上掉到 0.8889**（dev 0.9405）：排序质量对题目分布更敏感。论文里两条都报，不能只挑好的。

### 7.5 局限（写进论文"实验局限性"）

- 80 题对 33 份文档仍然偏少，每个制度平均只有 2–3 题。
- 关键词判定法偏宽：只要引用的块里"都出现这些字"就算命中，不判断是否真是正确答案那一句。
- 改写型只有 1 道（#45），无法单独统计"同义改问"的鲁棒性 → 下一步扩到 10 道。

## 八、改写型专项：扩到 11 道（2026-11-22 深夜）

### 8.1 目的

学生不会用制度原文的词提问（「挂科」vs「不及格」、「换专业」vs「转专业」）。原来题集只有 1 道改写型题，无法统计这一类。

本轮新增 10 道（id 81–90，dev 5 / test 5），题面用口语或同义词，关键词仍取制度原文，专门考「字面不匹配时还能不能召回」。题集总数 80 → **90 题**（88 道有效）。

### 8.2 结果（80 题集→90 题集；88 道有效 / 643 块 / 73 秒）

| 配置 | 总 Recall@3 | 总 MRR | dev | test |
|---|---|---|---|---|
| 纯向量 | 82.95% | 0.6951 | 85.11% | 80.49% |
| 纯 BM25 | 87.50% | 0.7973 | 91.49% | 82.93% |
| 混合 RRF | 92.05% | 0.8371 | 93.62% | 90.24% |
| 混合 RRF（不去重） | 93.18% | 0.8390 | 95.74% | 90.24% |
| 混合 + 精排 | 92.05% | 0.8504 | 91.49% | 92.68% |
| 合并相邻块 + 精排 | 94.32% | 0.8977 | 95.74% | 92.68% |
| 混合 + 展开邻居 | 94.32% | 0.8939 | 97.87% | 90.24% |
| **精排 + 展开邻居（线上）** | **96.59%** | **0.9148** | 95.74% | **97.56%** |

线上链路 dev 45/47 = 95.74%、test 40/41 = 97.56%；漏题 3 道：#2、#43、#84。

### 8.3 改写型 11 道的单独成绩（**结论与预期相反**）

| 配置 | 改写型命中 | Recall | MRR |
|---|---|---|---|
| 纯向量 | 9/11 | 81.82% | 0.6061 |
| 纯 BM25 | 10/11 | 90.91% | 0.8030 |
| 混合 RRF | **11/11** | **100%** | 0.8485 |
| 混合 + 精排 | 10/11 | 90.91% | 0.8182 |
| **精排 + 展开（线上）** | 10/11 | 90.91% | 0.8636 |

**我原来的假设被证伪**：我预期「纯 BM25 在改写型上明显弱于向量」。实测是 BM25 90.91% > 向量 81.82%，混合 RRF 甚至 11/11 满分。

### 8.4 为什么假设错了（这比数字本身更重要）

1. **我们的 BM25 分词是「单字 + 相邻双字」**，不是标准词粒度 → 「挂科」和「不及格」虽然不同词，但通过「科」「不」「及」等共用单字仍能匹配到一些分数，比标准分词宽容得多。
2. **我出的题"改写得不彻底"**：题面换了词，但和原文仍共享大量汉字（「电吹风/2000瓦」「超期违约金」「记过…评优」）。真正的硬改写应该做到**几乎零字面重叠**，例如「能拿助学金吗」vs 原文「家庭经济困难学生认定」。
3. **精排在这一类上反而掉了一道**（#84「军训不去会不会算旷课」）：精排按 query 与块的语义相关性打分，而正确块讲的是「考勤范围包含军训」，语义上不如别的块"像"这个问题。

### 8.5 下一步（已写进待办）

- 再补 10 道「零字面重叠」的硬改写题（例如：能拿助学金吗 / 上课迟到几次会被叫去谈话 / 宿舍插排能不能用 / 挂科两门会不会被劝退），重新验证"字面 vs 语义"的假设。
- 结论表述必须改成："在本文构建的 90 题集上，混合检索在改写型题上已达 100%，说明**我们这套单字+双字 BM25 的字面能力比预期强**；语义检索的优势需要更硬的改写样本才能显现。"

## 九、硬改写专项：假设这次成立了（2026-11-22 深夜）

### 9.1 这批题和上一批的区别

上一批（81–90）虽然换了词，但题面和原文平均仍有约 **0.5** 的汉字重叠；这一批（91–100）出题时刻意避开原文用字，平均重叠 **0.23**，最硬的 4 道是 **0.00**：

| 题面 | 原文关键词 | 字面重叠 |
|---|---|---|
| 借的书忘还了怎么算 | 逾期 \| 违约金 | 0.00 |
| 被记过多久能消 | 解除 \| 期限 | 0.00 |

题型单列为「硬改写」，题集 **100 题**（98 道有效）。

### 9.2 结果：纯 BM25 直接崩掉

| 配置 | 改写型（11 道，重叠≈0.5） | **硬改写（10 道，重叠≈0.23）** |
|---|---|---|
| 纯向量 | 9/11 = 81.82% | **6/10 = 60%** |
| 纯 BM25 | 10/11 = 90.91% | **2/10 = 20%** |
| 混合 RRF | 11/11 = 100% | 4/10 = 40% |
| 混合 RRF（不去重） | 10/11 = 90.91% | 5/10 = 50% |
| 混合 + 精排 | 10/11 = 90.91% | 4/10 = 40% |
| 合并相邻块 + 精排 | 10/11 = 90.91% | 6/10 = 60% |
| **精排 + 展开邻居（线上）** | 10/11 = 90.91% | **6/10 = 60%** |

**结论反过来了**：一旦题面和原文几乎不共享汉字，BM25 从 90.91% 掉到 20%，向量从 81.82% 掉到 60% 但仍然**是三维里最高的**。上一轮「BM25 更强」的判断只在"换词但共用汉字"的题上成立。

### 9.3 更值得注意的一层：混合检索被 BM25 权重拖累

硬改写上：向量 60% > 混合 RRF 40%。原因是线上用的是 **BM25 权重 0.8 / 向量 0.2**——当 BM25 完全没信号时，它把向量排出来的正确结果挤掉了。

这是一条可以直接做成改进的发现：**权重不该写死**。字面命中少的时候（BM25 分很低或 IDF 覆盖率很低），应该自动提高向量权重。这就是「按查询类型路由」的思路，也是很多工业 RAG 系统真实做法。

## 十、融合权重自适应（2026-11-22 深夜）

固定权重 `0.2 / 0.8` 在硬改写题上会反噬：混合 RRF 只有 **40%**，比纯向量 **60%** 还差。
加入「BM25 信号强不强」的判断后，混合回到 60%、线上链路到 70%。

但**总指标只多对 1~2 道题，dev 集上零变化**，所以这项改进按"机制有效、收益未证"处理，默认关闭。
