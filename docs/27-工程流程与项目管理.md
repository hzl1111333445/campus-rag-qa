## 二、目录职责（谁放在哪，别乱放）

| 路径 | 放什么 | 不许放 |
|---|---|---|
| `demo/src/main/java/com/campus/rag/controller/` | HTTP 入口：参数校验、调 service、组织响应 | 业务逻辑、SQL |
| `demo/src/main/java/com/campus/rag/service/` | 业务逻辑 + DAO | HTTP 细节（`HttpServletRequest` 之类） |

| `demo/src/main/resources/static/` | 前端构建产物（`npm run build` 后拷进来） | 手写调试页（旧版已改名 `legacy-debug.html`） |
| `frontend/src/views/` | 页面（一个路由一个文件） | 接口逻辑（放 `api/http.js`） |
| `docs/` | 编号文档：原理、评测、设计、日志 | 截图原图（放 `docs/images/`） |
| `docs/eval-runs/` | 评测原始快照 TSV（**证据**，别删） | 手工整理过的结论 |

| `data/testset/` | 评测题集（**源码级资产**，必须进 Git） | 临时导出 |
| `logs/` | 运行日志（已忽略） | 任何要提交的东西 |

## 三、一次改动的标准流程

```
① 开工前（3~5 行计划）
   要解决什么问题 → 会动哪 1~2 个文件 → 怎么验收 → 日志写哪里
        │
        ▼
② 动手（顺序：数据 → 后端 → 前端）
   结构变更先写 migration + 登记台账 + 同步 schema.sql
   接口只"加"不改：新字段走响应头 / SSE 新事件
        │
        ▼
③ 自测（四件）
   mvn compile → mvn test -Dtest=Xxx → curl（正常/越权/未登录）→ 前端 build
   涉及检索或生成：再跑一次 120 题回归，确认 gated 判定没变
        │
        ▼
④ 收工（三件）
   写 docs/04-工作日志.md「续 N」→ git commit -F（中文）→ 报告变更 + 原始输出 + 已知局限
```

## 四、可打印的自检清单

**开工前**

- [ ] 能用一句话说清"这东西坏了会怎样"
- [ ] 知道有谁在依赖它（前端页面 / `tools/*.py` / 评测脚本）
- [ ] 知道改完怎么验证

**提交前**

- [ ] 只碰了 1~2 个文件（多了有理由）
- [ ] 表结构变更写了 migration，并已在 `db/README.md` 登记
- [ ] 接口没改返回体结构，老脚本不受影响
- [ ] 编译通过（贴 exit code）
- [ ] 相关单测通过
- [ ] curl 覆盖了 401 / 403 / 400
- [ ] 前端 `npm run build` 通过 + 截图看过
- [ ] 跑过 120 题回归（如涉及检索/生成）
- [ ] 工作日志写了「续 N」
- [ ] `git status` 干净

**发布前（推到 GitHub / 给别人看）**

- [ ] `sk-` 扫描 0 命中（`git grep -n "sk-[A-Za-z0-9]\{20,\}"`）
- [ ] 无真实手机号 / 邮箱 / 密码明文
- [ ] 默认口令已在 README 标注"仅本地演示"
- [ ] README 里的数字与实际一致（类数、接口数、指标）

## 五、踩过的坑 → 已固化成规则

| 坑 | 后果 | 现在的规则 |
|---|---|---|
| 加表只改 `schema.sql` | 启动直接 `Table doesn't exist` | 必须写 migration + 台账（`db/README.md`） |
| `mysql -e "source x.sql"` 不带库名 | `ERROR 1046 No database selected` | 命令里必须带 `campus_rag` |
| 改 `/api/qa` 返回体 | 评测脚本当场断 | 新信息走响应头（`X-Session-Id` / `X-Message-Id`） |
| 脚本补丁拿"第一个 `}`"当锚点 | 方法插进 Javadoc，编不过 | 整文件重写，或用足够长的唯一上下文 |
| 一次改 5 个文件 | 出问题不知道是哪一处 | 一次 1~2 个文件 |
| 表格加列不重排列宽 | 列被挤成两行 | 列宽是配额，加列要重新分配 |
| 只在"未提交"状态下继续开发 | 回滚不了、也说不清哪步坏的 | 一个功能一提交 |

## 六、文档维护规则（2026-11-24 起）

| 规则 | 说明 |
|---|---|
| 一主题一文件 | 同一主题超过 3 份、且每份只有几 KB → 合并成一份，文首写「由 N 份合并」，每节标「出处」 |
