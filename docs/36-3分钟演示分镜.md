# 3 分钟演示分镜（照着录就行）

> 目标：让面试官在 3 分钟内相信三件事——**它能答、它答得有据可查、我知道它哪里不行**。
> 不讲架构，不讲代码；数字只说 3 个（90.68% / 51.7% / 0.44s）。

## 一、录制前 10 分钟准备

| 项 | 要求 |
|---|---|
| 服务 | `http://localhost:8081`（摘要开关开着的那个实例，`CONTEXT_SUMMARY_ENABLED=true`） |
| 账号 | `admin / admin123`（能进全部页面） |
| 浏览器 | Chrome，窗口 **1440×900**，缩放 100%，关掉书签栏；提前开好 1 个标签页 |
| 清理 | 清掉桌面通知；微信/QQ 退出登录；关掉输入法悬浮窗 |
| 预跑一遍 | 每段操作先自己点一次，确认数据在（会话列表、文档 35 份、块 663） |
| **Agent 模式开关** | **必须关掉**（右上角开关）。开着会报「Agent 模式未启用（后端 campus.agent.enabled=false）」；这个状态存在 localStorage 里，刷新不会重置 |
| 评测看板 | 录制前先点「跑一轮评测」，等它跑完（约 2 分钟）再录，否则结果表是空的 |
| 录制工具 | Win + G（系统自带）或 OBS；**只录浏览器窗口**，不录全屏 |
| 麦克风 | 用耳机麦，先录 10 秒试听；语速比平时慢 20% |

**录制纪律**：不要一次录完。**一段一条**，每段重录不要紧，最后剪。卡住就停，别说"呃"。

## 二、分镜表（总 3 分 00 秒）

### 第 1 段 · 0:00–0:20 · 这是什么（20 秒）

**屏幕**：停在登录页，不操作。

**旁白（逐字稿）**：
> 这是我在做的校园 AI 助手。学生用大白话问学校规章制度——旷课多少会被处分、宿舍几点关门、转专业能申请几次——系统给答案，**并且每条答案都能点回原文**。答不出来的时候它会直接说"没查到"，而不是编一个。

**要点**：只讲"解决谁的什么问题"，不报技术栈。

---

### 第 2 段 · 0:20–1:05 · 主场景：能答 + 可溯源（45 秒）

**屏幕操作**：
1. 输入 `admin / admin123` → 登录
2. 在输入框打：**旷课多少学时会被处分？** → `Ctrl + Enter`
3. 等回答出来（约 1.5 秒首字），**停 2 秒**让画面读得完
4. 用鼠标依次指三个徽章：`引用校验通过` → `接地通过·核了 10 条`
5. 点 `出处 [1] 广州软件学院学生考勤管理制度` 后面的 **`看原文`** → 展开原文块，**停 2 秒**
6. 收起

**旁白**：
> 问一句"旷课多少学时会被处分"。它先检索，再让模型**只根据检索到的条款**回答。
> 答案上面有三个校验：引用编号是不是真的存在、答案里的数字和档位是不是真在那段原文里。
> 点"看原文"能直接跳到条款原文——**这是这个项目和普通聊天机器人最大的区别**：不是"看起来对"，是"能核对"。

**兜底**：如果这题答得不好，换成 `考试作弊会怎么处理？`（同样有分档条文）。
**注意别用「保研需要什么条件」**：实测相关度 0.0198 高于阈值，系统仍会作答并标 `无可核对硬事实`——不是干净的拒答画面。

---

### 第 3 段 · 1:05–1:35 · 关键能力：不会就说不会（30 秒）

**屏幕操作**：
1. 输入：**火星基地的食堂几点开饭？** → `Ctrl + Enter`（实测：相关度 0.0121 < 阈值 0.015，570ms 返回）
2. 出现三个灰徽章：`未检索到相关资料` / `未引用资料` / `无可核对硬事实`
3. **鼠标指底部那行**：`3 块 · 最高相关度 0.0121`

**旁白**：
> 再问一个库里根本没有的：火星基地的食堂几点开饭。它就**直接拒答**，还把最高相关度告诉你——0.0121，低于阈值 0.015。
> 这个"敢于拒答"是标定过的：库内能答的题最低相关度 0.2 左右，库内没有的题最高只有 0.0025 上下，中间空了 80 倍，所以阈值定在 0.015。
> 拒答在检索层完成，**连大模型都不调用**，响应 0.44 秒。

**要点**：这一段是"我知道边界"，比第 2 段更加分。

---

### 第 4 段 · 1:35–2:10 · 数据怎么进去的（35 秒）

**屏幕操作**：
1. 点左侧 **文档管理**
2. 鼠标划过顶部两个数：`文档 35 份` / `块 663`
3. 找到《广州软件学院学生考勤管理制度》这一行（ID 43），点 **看块**
4. 抽屉打开后，**滚动看两三个块**，让"块头【11-广州软件学院学生考勤管理制度·第四章…】"露出来
5. 关掉抽屉

**旁白**：
> 左边是文档管理。上传后自动解析、切分、向量化，现在是 35 份规章、663 个块。
> 点"看块"能看到每一块长什么样——**块头带文档名和章节**，因为它会作为检索单元被送进提示词，带上出处模型才知道自己在引用哪一条。
> 切分参数是调出来的：一开始 748 块、平均 99 字，太碎，改完是 305 块、平均 195 字。

---

### 第 5 段 · 2:10–2:40 · 为什么它敢改（30 秒）

**屏幕操作**：
1. 点左侧 **检索调试**
2. 输入 **借的书忘了还怎么算** → 点 `检索`
3. **鼠标横扫五列标题**：纯向量 / 纯字面 BM25 / 混合 RRF / 混合+精排 / 精排+展开邻居
4. 指最右边一列的绿色格子，再指下方 `③ 线上链路与拒答闸门` 那行：`最高分 0.8840 / 阈值 0.015 / 正常作答`
   - 注：默认 `REWRITE_ENABLED=false`，查询理解里会显示「改写器已关闭」。想让它更完整可开改写（每次多约 1 秒）

**旁白**：
> 这是检索调试页：同一个问题，五条链路各自召回什么，一眼能看出来哪一步漏了。
> 底下是线上真实链路：混合检索 → 精排 → 展开邻居 → 阈值判断。
> **我每次改检索都在这里对照**，不是凭感觉。

---

### 第 6 段 · 2:40–3:00 · 收尾：我自己评过（20 秒）

**屏幕操作**：
1. 点左侧 **评测看板**（若已有上一轮结果表，直接指表）
2. 指表头那行字：`题集 120 题 · 配置 13 种`，再指第一行 `双查询融合 + 精排 + 展开` 的 `90.68%`
3. 如果表是空的：点 `跑一轮评测`，看到进度条出现就切走（**不要等**）

**旁白**：
> 最后是评测看板。我自己建了 120 道题的评测集，13 种检索配置全部跑过一遍，线上 Recall@3 是 90.68%。
> 端到端严格正确率 51.7%，含部分正确 78.8%——**这个数字不好看，但它是量出来的**，而且我做过 badcase 归因：65% 的失败在生成层，不是检索。
> 所以下一步该动哪里，是数据告诉我的。

**结尾一句（镜头停住说完）**：
> 代码和 34 篇文档都在 GitHub 上，从第一天到现在的每一步都有记录。

## 五、三句"别说"的话

1. 别说"这个系统用了 RAG 技术"——**说"它先查资料，再让模型照着资料回答"**。
2. 别说"准确率 90.68%"——那是**检索命中率**；端到端是 51.7%（含部分 78.8%）。混着说会被追问穿。
3. 别说"还差很多没做完"——说"已知瓶颈在生成层与语料覆盖，评估过"，这是判断力，不是心虚。
