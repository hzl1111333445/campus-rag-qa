# 34 · 长会话记忆与上下文摘要

> 目标：给"多轮会话记得住"这件事建立**可复现的基线**，再决定要不要做摘要压缩。  
> 方法：20 轮任务型会话 × 5 个场景，探针题不带条件，看回答里是否用上了早期交代的条件。

## 1. 为什么做这个

现在 `ContextAssembler` 只带最近 **3 轮 / 单条 120 字 / 总 600 字**，第 4 轮开始就看不见第 1 轮说的话。
实测真实会话平均只有 1.15 轮，所以这不是"线上故障"，而是**能力缺口**：换到任务型多轮（要追问 3~5 轮才够条件）就会立刻暴露。

先量基线，是为了避免"写完了也不知道有没有用"。

## 2. 评测设计

- 用例：`tools/eval_multiturn.py` 内置 5 个 20 轮会话
  - S1 转专业（大一 / 绩点 3.6 / 无挂科 / 目标软件工程）
  - S2 奖助学金（大二 / 困难认定已过 / 专业前 10%）
  - S3 宿舍晚归（3 栋 / 本月三次 / 已有记过）
  - S4 挂科重修（数据结构 58 / 大一 / 想保研）
  - S5 旷课（每周三节 / 累计 18 学时 / 未请假）
- 探针：每个会话在第 5、11、15、20 轮问一个**不带条件**的问题（如"那我这样的情况能满足条件吗"）
- 判定：
  - `retained`：回答里出现早期条件词（大一 / 3.6 / 软件工程…）
  - `lost`：回答反问已给过的信息
  - `neutral`：两者都没有（多为检索拒答）
- 限流：`/api/qa` 30 次/分钟，脚本按 2.2 秒间隔发送，撞 429 按 `retryAfterSeconds` 重试

复跑：

```powershell
& $py tools\eval_multiturn.py            # 全量（约 4 分钟）
& $py tools\eval_multiturn.py --limit 1 --turns 5
```

## 3. 基线结果（2026-11-25，未做摘要）

| 会话 | 保持 | 说明 |
|---|---|---|
| S1 转专业 | 1/4 | 第 5 轮记住了绩点 3.6；第 11 轮起失忆；第 15/20 轮被检索拒答 |
| S2 奖助学金 | 1/4 | 第 5 轮完整复述"你大二、困难认定已通过、排名前 10%"；第 15/20 轮只列通用条件 |
| S3 宿舍晚归 | 4/4 | **假阳性**：关键词本就在条文里，回答实际说的是"仅凭'我这情况'无法判断" |
| S4 挂科重修 | 1/4 | 保研/重修细则**不在语料**，四题全是"暂未收录" |
| S5 旷课 | 3/4 | 第 5 轮答对（18 学时未达 20）；第 15 轮失忆（说"你没说明具体情形"）；第 20 轮拒答 |
| **合计** | **10/20 = 50%** | 但这个 50% 高估了记忆能力 |

### 手工复核后的真实分布

| 类别 | 数量 | 说明 |
|---|---|---|
| 真·记住了条件 | **5** | 全部出现在**第 5 轮**（S1/S2/S3/S5 各 1，S4 t5 靠检索碰巧命中） |
| 第 10 轮及以后真记住 | **0 / 9** | 6 轮之后无一次真正用上早期条件 |
| 关键词假阳性 | 5 | S3 全部四题 + S5 t15 |
| 检索拒答（相关度 < 0.015） | 6 | 探针问题本身太泛（"我现在的条件还差什么"） |
| 题目超出语料 | 4 | S4 的保研/重修细则不在 35 份制度里 |

**结论：3 轮窗口的边界就在第 4~5 轮。第 5 轮 5/5 记住，第 11 轮起 0/9。**
这批数字直接支撑"要么扩窗、要么摘要"，而不是凭感觉。

## 4. 评测本身要修的三个问题

1. **关键词假阳性**（最严重）：`expect` 里的词常在条文原文里出现，导致"答非所问"也被判为 retained。
   → 改法：判"是否复述了用户给的具体值"（3.6 / 58 / 18 / 三次）+ 是否明确说"你没说明情况"（判 lost）
2. **探针太泛**：`我现在的条件还差什么` 检索相关度只有 0.0013，被阈值拦掉，量到的是检索问题不是记忆问题。
   → 改法：探针改用"承接型指代"（`那我这样能过吗`），并把"拒答"单独记一类，不算失忆
3. **题目超出语料**：S4 的保研要求根本没收录
   → 改法：每个场景先确认 3 条判据都在库内（`docs/12` 缺口清单）

## 5. 下一步（按 §11 四段提案）

### 6.2 预算表（与 DSH 的关系）

| 参数 | 我们 | DSH（`billion-context`） | 为什么不同 |
|---|---|---|---|
| 窗口 | 1200 token | 模型真实窗口的 75% | 我们的"历史预算"是自定的 600 字，不是模型上限 |
| 触发 | 60% | 75% | 消息比 DSH 的工具输出短，早触发才来得及 |
| 紧急 | 90% | 95% | 留一次摘要调用的余量 |
| 增长门槛 | 300 token | 50000 token | 按 1/160 同比缩（防高频小折） |
| 保护带 | 最近 5 轮 / 600 token | 3 条 / 5000 token | 我们要保住"上一轮问了什么" |
| 摘要上限 | 240 字 | 20000 字 | 摘要进提示词，越长越挤资料 |
| 二次摘要 | 禁止（并集去重，不润色旧摘要） | 分层递进 | 递归润色是失真主因 |

### 6.3 三次 20 轮评测（同一套题、同一台机器）

| 运行 | 配置 | 关键词口径 | 人工复核要点 |
|---|---|---|---|
| 基线 | 无摘要、历史含问答 | 10/20 = 50% | 真保留只有 5 个且全在第 5 轮；第 11 轮起 0/9 |
| 第一次 | 摘要开、历史含问答 | 9/20 = 45% | 摘要生成了，但**没进提示词**（见 6.4 的三个 bug） |
| 第二次 | 摘要开、**历史只留用户提问** | **12/20 = 60%** | S3 从"假阳性"变成真的用上"本月晚归三次"；S2 第 15/20 轮从泛化条件变逐条对照 |

**逐案看变化（这比总分重要）**

- `S3-宿舍`：基线第 11 轮答"仅凭这次无法判断"（判 retained 是关键词假阳性）；摘要后答"你本月晚归三次，按此规定属于会被处分的情形"——**这是真正的"记住"**。
- `S2-奖学金`：基线第 15/20 轮只列通用条件；摘要后能对着"大二 / 无补考 / 未受处分"逐条比对。
- `S5-旷课`：第 5 轮反而**退化**——基线答"18 学时未达处分标准"，摘要版答"找不到对应规定"。原因是历史只剩提问、丢掉了上一轮答案里的"18 学时"表述框架。→ 说明"只留用户提问"有代价，不是纯赚。
- `S1/S4`：基本没变，因为失败原因是**检索拒答**（相关度 0.0013）与**语料缺失**（保研细则没收录），跟记忆无关。

### 6.4 修掉的三个真 bug（都会静默失败）

1. **触发条件看错对象**：原实现拿"待折片段"的 token 去比窗口，而保护带外的片段永远很小 → 20 轮会话也永不触发。改成用**整段历史**的 token 判断。
2. **库里存了渲染后的文字**：下次折叠要在此基础上做并集，`readTree` 解析失败被 catch 吞掉 → `facts` 每次被清空、摘要越折越短（59 → 46 字）。改成**存 JSON、读时渲染**。
3. **助手自我强化**：历史里带自己的旧回答，模型把"我说过的话"当成"用户的情况"，同一句"你上学期有作弊记录"连续两轮出现（用户从未说过）。改法两条：`include-assistant=false`（历史只留用户提问）+ 提示词显式声明"用户问过什么 ≠ 用户自己是什么情况；没写进摘要的一律当作没说过"。
   → 修复后同一问题回答变成"**你自述未受处分**，但资料未涉及旷课 18 学时的认定，建议向辅导员确认"，不再编造作弊记录。

### 6.5 结论（诚实版）

- 摘要机制**能成立**：结构化 JSON（`goal/facts/open`）、增量折叠、确定性并集、可开关、可查看、失败不影响回答。
- 但 20 轮指标**只从 50% 抬到 60%**，而且其中仍有 1~2 个关键词假阳性。真正的瓶颈不是"记不住"，是**检索拒答**（探针太泛直接 0.0013）与**语料缺口**（保研/重修没收录）。
- 所以下一步不该继续调摘要，而该修评测判分（判"是否复述用户给的具体值"）+ 补 `docs/12` 里的语料缺口。
- 默认 `CONTEXT_SUMMARY_ENABLED=false`：保持线上行为不变，需要时开开关，用同一套 20 轮脚本做 A/B。

**验收结果**：`第 10 轮及以后真保留` 从 0/9 提升到可观察（S3/S2 在第 11/15/20 轮真的用上了早期条件），但未达"≥6/9"的原定目标——原因已定位到检索与评测口径，不是摘要本身。
