# 校园规章 RAG 问答系统 · 阶段性总结（检索与生成链路定稿）

> 时间：2026-11-22 夜。范围：从"上传一个 PDF"到"端到端回答评测"，即 RAG 全链路（不含前端工程期）。
> 用途：①写论文第五章/第六章的素材底稿 ②面试自述的骨架 ③下一阶段（前端 + 部署）的交接文档。

---

## 1. 系统做了什么

用户（学生）用大白话问校园规章问题，系统回答并给出原文出处，答不了就说"本知识库暂未收录"。

```
离线：PDF/DOCX/TXT → 解析(Tika) → 切分(220/50) → 块头补【文档·章节】 → bge-m3 向量化(1024 维) → MySQL
在线：问题 → 查询改写(信号<1.5 才触发) → 双查询融合 → 向量+BM25 双路 → RRF(k=60) → 相邻块去重
     → Cross-Encoder 精排(Top10→3) → 展开邻居块 → 阈值 0.10 拒答 → DeepSeek 生成
     → 引用编号校验 → 接地校验(硬事实核对)
```

## 3. 检索侧：做了哪些取舍，各自值多少

### 3.1 十三种配置（118 应答题 × 643 块）

| 配置 | Recall@3 | MRR | 硬改写(30) |
|---|---|---|---|
| 纯向量 | 75.42% | 0.6271 | 53.3% |
| 纯 BM25 | 77.12% | 0.6822 | 46.7% |
| 混合 RRF | 80.51% | 0.7274 | 46.7% |
| 混合（不去重） | 84.75% | 0.7415 | 60.0% |
| 混合 + 精排 | 82.20% | 0.7500 | 53.3% |
| 混合 + 合并相邻块 | 85.59% | 0.8150 | 66.7% |
| 合并 + 精排 | 88.14% | 0.8192 | 70.0% |
| 混合 + 展开邻居 | 87.29% | 0.8220 | 66.7% |
| 精排 + 展开（原线上） | 89.83% | 0.8333 | 70.0% |
| 混合 + 查询改写 | 86.44% | 0.7669 | 66.7% |
| 改写 + 精排 + 展开 | 89.83% | 0.8475 | 73.3% |
| 混合 + 双查询融合 | 83.05% | 0.7500 | 53.3% |
| **双查询融合 + 精排 + 展开（线上）** | **90.68%** | **0.8531** | **76.7%** |

### 3.2 每一步的净收益（谁在起作用）

| 改动 | 收益 | 结论 |
|---|---|---|
| BM25 + 向量 双路 | 混合 vs 单路：+3~5pt | 两路互补成立 |
| 精排（Cross-Encoder） | +5~7pt（含排序质量） | 有效 |
| 展开邻居块 | MRR +0.03~0.05 | 有效，且不加成本 |
| 查询改写（LLM） | 硬改写 70%→76.7%，总 89.83%→90.68% | 有效 |
| 双查询融合 | 硬改写 +3.4pt，但需另配权重 | 有效（权重 0.5） |
| **自适应融合权重** | 硬改写 60%→70%，但 dev 集零变化 | **未达显著，默认关闭** |
| **两段式生成** | 幻觉 -3.3pt 但误拒 +4.2pt | **净收益为零，默认关闭** |

### 3.3 三个诚实的技术结论

1. **检索已经接近上限**：46 道答不好的题里只有 16 道与检索有关，**65% 是"资料在 Top3、模型还编"**。
2. **硬改写是真短板**：口语问法 Recall@3 只有 76.7%（"寝室能通宵打游戏吗"原文写"作息""熄灯"）。这不是调参能修的，要 doc2query / 术语表。
3. **关键词命中 ≠ 答案完整**：现有 Recall 口径偏宽（"块里出现全部关键词"就算命中），论文里必须声明这条局限。

## 4. 生成侧：幻觉治理的三层与代价

| 层 | 做法 | 效果 |
|---|---|---|
| 检索层 | 分数阈值拒答（0.015），资料太不相关就不调模型 | 拒答响应 **1.7s → 0.44s**；误拒 5.1% |
| 提示词层 | 8 条硬规则（禁替学校下结论 / 数字须逐字 / 不复述问题 / 200 字内…） | 幻觉 48.3% → **34.7%**；答案 223→123 字 |
| 校验层 | 引用编号越界校验 + 接地校验（数字/期限/处分名逐个回原文核） | 引用合法率 120/120；接地不合格会打警告并在前端标黄 |

### 4.1 端到端三版对照（118 应答题）

| 版本 | 严格正确 | 含部分正确 | 幻觉 | 误拒 | 延迟 |
|---|---|---|---|---|---|
| 基线 | 48.3% | 80.5% | 48.3% | **7.6%** | 1.39s |
| 提示词硬化 | 52.5% | 76.3% | 33.1% | 10.2% | 1.17s |
| 硬化 + 阈值 0.015 | 51.7% | **78.8%** | 34.7% | **5.1%** | 1.39s |
| 两段式（负结果） | 51.7% | 79.7% | **31.4%** | 9.3% | 2.05~2.40s |

### 4.2 42 个点丢在哪（相对检索上限 90.68%）

| 环节 | 损耗 |
|---|---|
| 检索没给到（9.3pt） | 90.68% → 81.4% |
| 有资料但加料（部分正确 32.2pt） | → 49.2% |
| 误拒（5.1pt） | → 44.1% |
| 真错（5.1pt） | → 38.9% |

> 注意：这是按"严格正确"口径拆的账，各段交叉统计，只用于说明"主要矛盾在加料"。

## 5. 工程化设计（面试问"你踩过什么坑"就用这些）

| 设计 | 为什么需要 |
|---|---|
| **配置指纹**（`config_hash = sha256(模型+维度+切分参数)`） | 换 embedding 模型或切分参数后，旧向量不会静默失效，而是检索时直接报"需要重新导入" |
| 文档状态机（待处理/处理中/成功/失败） | 上传 33 份里 14 份扫描件失败，失败原因要能回显、能重试 |
| OCR 走 Windows 自带引擎（winocr） | 无需 Tesseract/PaddleOCR，107 页 33 秒，单页 0.22s |
| 长文档按"篇"切分 | 《学生手册》9.6 万字按 26 个制度边界切成 8 篇，避免制度混在一起 |
| 块头补【文档·章节】 | 块脱离上下文后仍知道"这条来自哪份文件的哪一章" |
| 阈值分两把尺子 | 精排分 0~1、混合分 0.0x，量纲差 20 倍，必须分开配 |
| 引用编号 + 接地双校验 | 前者防"标了不存在的出处"，后者防"出处合法但内容张冠李戴" |

## 6. 被证伪 / 白做的实验（论文里写"负结果"，面试里讲"判断力"）

| 实验 | 预期 | 实际 | 处理 |
|---|---|---|---|
| 自适应融合权重（BM25 信号弱就让权重给向量） | 硬改写 +10pt | 只多对 1~2 道，dev 零变化 | 默认关闭，只留接口 |
| 两段式生成（先摘原句再组答案） | 严格正确 +10pt | 幻觉 -3.3pt、误拒 +4.2pt、正确率持平 | 默认关闭，留开关 |
| 双查询融合权重误用 0.2（借了向量权重） | — | 结果与纯混合完全相同 = 白测一次 | 独立配置 `fusion-w-rewritten: 0.5` |
| "把模型答对的内容写进向量库" | — | badcase 分类显示**库内零缺失**，没有需求 | 否决，避免循环自证 |

## 7. 局限（必须写进论文）

1. 题集 120 题对 643 块仍偏少，每份制度平均 3.6 题。
2. 关键词命中口径偏宽，未测"证据覆盖率"（Top3 能否支撑完整答案）。
3. LLM 裁判有抖动：同一题跨版本判分不一致（#55 基线"正确"、新版"拒答正确"），±2~3 道不可信。
4. 单机单实例、无并发压测；未做多轮对话（无 session 持久化到前端）。
5. 语料只有一所学校，跨校泛化未验证。
6. 硬改写的 30 道题是本项目自建的，改写强度由作者主观控制。

## 9. 一句话总结（面试自述用）

> 我做了一个校园规章 RAG 问答系统：手写 BM25 + 向量双路召回、RRF 融合、Cross-Encoder 精排、查询改写与双查询融合，
> 在自建 120 题评测集上把检索 Recall@3 从 75%（纯向量）做到 90.68%；
> 端到端答对率 51.7%、含部分正确 78.8%，幻觉率从 48.3% 压到 34.7%；
> 中间做过两个最终被我自己否掉的方案（自适应权重、两段式生成），都有 A/B 数据。
